# 每日班表辨識器

這是一個 React 前端＋FastAPI 後端的小工具。後端會把完整原始照片與保留時間軸的放大圖交給 OpenAI 視覺模型，找出「己／蕭志明」在下列五種班別的逐時紀錄：

- 國際線（需要工作）
- 國際線（二）（休息）
- 國際線備勤（休息）
- 國內線一線（需要工作）
- 國內線二線（休息）

程式會同時顯示完整班表，並把真正需要工作的相鄰時段自動合併。低信心或模糊的格子會標成「需確認」。

## 安裝後端

需要 Python 3.10 以上。

```bash
cd work_scheduler
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

到 OpenAI API 平台建立 API key，然後只在目前的終端機工作階段設定：

```bash
export OPENAI_API_KEY="你的_API_Key"
```

或複製 `.env.example` 為 `.env` 並填入金鑰；後端啟動時會自動載入。

請勿把 API key 寫進程式、README 或提交到版本控制。

## 一次啟動前後端

```bash
cd work_scheduler
./.start_dev.sh
```

按 `Ctrl+C` 就會同時停止前端與後端。腳本會優先使用專案的 `.venv/bin/python`；若沒有虛擬環境，則使用目前的 `python3`。兩個連接埠已有其他服務時，腳本會先停止並提示，不會蓋掉既有程序。

## 分別啟動

```bash
uvicorn backend.app:app --reload --port 8010
```

API 文件會在 <http://127.0.0.1:8010/docs>，健康檢查在 <http://127.0.0.1:8010/api/health>。這裡刻意使用 `8010`，避免和其他常用 `8000` 的 FastAPI 專案衝突。

## 啟動 React 前端

另開一個終端機：

```bash
cd work_scheduler/frontend
npm install
npm run dev
```

開啟 <http://127.0.0.1:5173>。Vite 開發伺服器需要把 `/api` 送到後端；專案已在 `vite.config.ts` 設定好 proxy。

正式環境若前後端不同網域，可建立 `frontend/.env.production`：

```text
VITE_API_BASE_URL=https://你的後端網域
```

## 保留的命令列用法

```bash
python schedule_reader.py /完整路徑/今日班表.jpg
```

需要讓其他程式接續處理時，可輸出 JSON：

```bash
python schedule_reader.py /完整路徑/今日班表.jpg --json
```

也可以透過 `OPENAI_MODEL` 或 `--model` 更換有影像理解能力且支援 Structured Outputs 的模型：

```bash
python schedule_reader.py 今日班表.jpg --model gpt-5.4-mini
```

## 測試

```bash
python -m unittest -v
```

伺服器的 Docker 映像用的是 Python 3.11（`Dockerfile` 的 `python=3.11`）。`test_server_python.py` 會用那個版本把所有程式檔讀一遍：測試本身就在 3.11 上跑時直接用它，否則找電腦上的 `python3.11`，兩個都沒有才略過。這樣只有新版 Python 才看得懂的寫法（例如 f-string 裡面再用同一種引號包 f-string，要 3.12 以上）不會在新版上測試全過、部署後機器人卻連啟動都不行。

注意：照片辨識仍可能出錯，尤其是格線歪斜、低解析度、反光或手寫覆蓋時。正式排班請以原始表單為準，看到「需確認」時務必人工核對。

## 本機 ResNet 格子分類器

這套工具把既有 LINE 模擬中的逐格 PNG 去重後，建立 `丁／戊／己／庚`
四標籤資料集。同一格可以選取多個字；四項都不選代表空格、數字、英文字母或其他中文字。

```bash
python -m pip install -r requirements-train.txt
python roster_resnet.py prepare
python roster_resnet.py label
```

若原始班表照片集中在 `data/schedules/`，可直接在本機做透視校正與逐格裁切；此命令
不會呼叫 OpenAI API，並會依照片內容雜湊保留既有人工標籤：

```bash
python roster_resnet.py ingest
python roster_resnet.py label
```

標註頁上方可直接選擇 JPG、PNG 或 WEBP 照片，按「上傳、切格並自動標註」。
照片會保存至 `data/schedules/`，自動切成 06–20 的目標格，並以目前 checkpoint
產生丁／戊／己／庚建議。淺藍底只是模型預標註，不會算作人工完成資料；必須目視
修正並按下儲存後，才會寫入正式標籤。

標註介面一次顯示一整張班表的 14×16 個目標格。先按人物按鈕或快捷鍵
`1` 丁、`2` 戊、`3` 己、`4` 庚，再點擊該人物所在的所有格子；再次點擊會取消。
同一格若有多人，可切換人物後再次點選同一格。四人都標完後按 `Enter` 或
「完成本張並儲存」，沒有點選的項目會一併記為負樣本，再自動前往下一張。
左右方向鍵可切換班表。只有看見完整、獨立的目標字才選取；其他內容全部保持
未選。標籤會寫入 `data/roster-resnet/labels.csv`，可中斷後再繼續。

可隨時查看完成度與每個字的正樣本數：

```bash
python roster_resnet.py status
```

完成標註後訓練及評估：

```bash
python roster_resnet.py train
python roster_resnet.py evaluate --split test
```

訓練期間可在另一個終端啟動即時監控頁面：

```bash
python roster_resnet.py monitor
```

瀏覽器會開啟 `http://127.0.0.1:8766`。頁面每兩秒讀取
`models/roster-resnet18.json`，顯示 epoch、loss、validation macro F1、最佳 epoch，
以及丁／戊／己／庚各自的 precision、recall、F1 和歷史曲線。訓練程式會在每個
epoch 結束時以原子方式更新報告，因此監控頁不會讀到只寫了一半的 JSON。

訓練會以整張來源班表分組切成 train／validation／test，避免同一天的格子洩漏到
不同集合。最佳權重寫入 `models/roster-resnet18.pt`，評估報告會分別列出四個字的
precision、recall、F1 與測試樣本數。

LINE／模擬流程現在預設載入最佳本機 ResNet checkpoint，不再用 Luna 判讀格子，
也不再呼叫文字模型整理結果。預設檔案是 `models/roster-resnet18.pt`；如需改用其他
checkpoint，可在 `.env` 設定：

```text
ROSTER_RESNET_CHECKPOINT=/app/models/roster-resnet18.pt
```

Docker 部署時需將訓練完成的 checkpoint 放入專案 `models/`。正式 requirements
已包含 PyTorch；checkpoint 不存在時會明確停止，不會默默退回 Luna。

## Discord 自動回覆班表

### 使用 Docker 執行 Bot

Docker 映像會建立名為 `work` 的 Conda 環境，並以該環境執行 `python discord_bot.py`。先依 `.env.example` 建立 `.env` 並填入 `DISCORD_BOT_TOKEN`、`OPENAI_API_KEY`，再執行：

```bash
docker build -t work-schedule-discord .
docker run --rm --env-file .env \
  -v "$(pwd)/data:/app/data" \
  work-schedule-discord
```

掛載 `data` 會保留 API 用量資料庫；容器停止可用 `Ctrl+C`。

或改用 Compose，以背景方式重建並重新啟動 Bot：

```bash
chmod +x dockercompose_restart.sh
./dockercompose_restart.sh
```

即時查看 Bot 日誌可執行 `docker compose logs --follow`；停止服務可執行 `docker compose down`。

上傳一張照片後，Bot 會回覆四份班表：丁／簡志明、戊／葉雅婷、己／蕭志明、庚／莊雅婷。逐格辨識範圍為 `06-07` 至 `19-20`，可涵蓋晚班；證據圖在 `20:00` 邊界停止，不包含姓名表與附註。

Discord 不顯示警告圖示或「辨識提醒」區塊，列出合併後的工作、休息及逐時班表。若某員工完全沒有辨識到任何時段，會顯示「當日休假」；只辨識到部分時段時仍會顯示「時段尚未完整」。休息只由看見的休息勤務計算，不把空檔算成休息。8 格完整僅代表時段數量完整，不能保證辨識正確；不再強制6工2休，原圖可能是5工3休。網頁仍顯示蕭志明單人結果。

四份回覆後會附上本次 API 次數、輸入／輸出 tokens、前處理／總耗時、本次與開始記錄以來的累計估計費用。記錄儲存在 `data/api_usage.sqlite3`（可用 `API_USAGE_DB` 改位置）；重啟不會歸零。只存模型、回應ID、用量、費率與估價，不存圖片或提示詞。每個收到的 API 回應在解析前記錄，因此格式錯誤的回應也會被計入；網路逾時而未收到回應的費用無法得知。舊版未留用量，因此無法回推之前9分鐘那次的精確費用。

費率查核日2026-09-09，來源為 [OpenAI官方標準API費率](https://developers.openai.com/api/docs/pricing)。`gpt-5.6-luna` 短上下文每百萬tokens：輸入US$0.20、快取讀取US$0.02、快取寫入US$0.25、輸出US$1.20。使用回應的usage估算，輸出包含推理tokens，不能再重複加計；超過272K輸入使用長上下文費率。未支援的模型／服務級別顯示無法估算。費率表可能變動，稅金、區域加價與帳戶優惠不在此估算內，帳單以OpenAI為準。

如需以原始照片做實際API驗證（會产生費用），可執行：

```bash
python benchmark_roster.py /path/to/1952955.jpg --output /tmp/roster-result.json --expected tests/fixtures/1952955_expected.json
```

`--expected` 是這張照片的人工核對基準，只供比對測試，不會送入模型或用於覆寫辨識結果。驗證新的照片時請省略此參數或建立對應基準。

Bot 可以監看一個 Discord 頻道：使用者直接丟入 JPG、PNG 或 WEBP 班表照片後，Bot 會在該訊息下方回覆工作時段、逐時班別與辨識提醒。照片只會暫存在辨識期間的臨時資料夾，完成後自動刪除。

1. 到 [Discord Developer Portal](https://discord.com/developers/applications) 建立 Application，進入 **Bot** 頁面後建立 Bot 並複製 token。
2. 在 **Bot → Privileged Gateway Intents** 開啟 **Message Content Intent**。
3. 在 **OAuth2 → URL Generator** 勾選 `bot`，Bot Permissions 選 `View Channels`、`Read Message History`、`Send Messages`、`Attach Files`，用產生的網址邀請 Bot 加入你的伺服器。
4. 在專案根目錄複製 `.env.example` 為 `.env`（不要提交）並填入：

```text
OPENAI_API_KEY=你的_OpenAI_API_Key
DISCORD_BOT_TOKEN=你的_Discord_Bot_Token
# 選填：只讓 Bot 回覆這個頻道。開啟 Discord 開發者模式後，右鍵頻道複製 ID。
DISCORD_CHANNEL_ID=123456789012345678
```

5. 安裝更新後的依賴並啟動：

```bash
python -m pip install -r requirements.txt
python discord_bot.py
```

看到 `已登入 Discord` 後，在指定頻道傳一張班表圖片即可。若不設定 `DISCORD_CHANNEL_ID`，Bot 會在它有權限看到的所有頻道處理圖片。

## LINE V2：群組安靜收圖，私訊查詢與通知

全員版（`python -m all_staff.cli line-bot`／Compose 的 `work-schedule-line-v2`）採用以下流程。
群組只提供班表照片與每日的航班人數訊息，機器人不在群組發歡迎訊息、辨識結果、錯誤或指令回覆；設定與查詢都在私訊完成。

### 初次設定

機器人只服務安檢隊，不需要建立或連接單位，也沒有加入碼。

1. 在 LINE Developers Console 開啟 **Allow bot to join group chats**，並邀請 V2 官方帳號加入隊長發布班表的群組。關閉官方帳號後台的自動回應，避免後台設定另行發訊息。LINE 自己顯示的「已加入群組」系統訊息不受機器人控制。
2. 在群組公告機器人的好友連結／QR code，之後隊長照常發布照片即可。

機器人所在的任何群組收到的班表照片都會當作全隊最新班表。

同一天（以班表上印的日期為準）有多張照片時，以 **LINE 訊息傳送時間最晚**的一張為準，不是辨識完成的先後：
後傳的更新版會通知已開通知的人「🔄 班表更新」，並註明「你的勤務與上一版相同／不同」（讀不到上一版時不註明）；
較早傳、較晚才辨識完成的舊版本只會存檔，不通知也不會取代新版。日期讀不到的照片無法比對，一律當作新班表；設定管理員、而且推播開啟時則先請管理員確認日期（見「管理員：日期讀不到時先確認再通知」），預設不推播時直接發布，管理員在辨識回報上補日期。
群組裡不是班表的圖片（頭像、截圖、貼圖）不存成班表，群組裡也不回覆；傳過班表的人傳了這種圖片會收到無法辨識的提醒（可能是班表拍壞了），其他人不會。設定管理員後，每一張都會回報給管理員（見「管理員：群組照片的辨識回報」）。

### 不推播（預設）：不用訊息額度

LINE 免費的輕用量方案每月只有 200 則推播（push），每次推播以收件人數計；同仁自己傳訊息、按選單、傳照片時機器人給的回覆（Reply）不計額度。
所以機器人**預設完全不推播**：本來要主動私訊某個人的訊息，一律先放進那個人的「收件匣」（資料庫的 `mailbox` 表），等他下次傳訊息或按選單、機器人回覆他的時候，放在那次回覆的前面一起送出（Reply，免費）。

- **會放進收件匣的**：給管理員的群組照片辨識回報（回報卡片和勤務人員原圖是同一組）、群組航班人數訊息的讀取結果、姓名申請卡片；給申請人的審核結果（只有那一句，不附 `我的班表` 卡片：晚一點才看到時，卡片上的「下個小時」早就過了；那句話會請他點「我的班表」）；群組班表無法辨識時給上傳者的提醒（寫明是幾月幾日幾點傳的那張，「這張沒有更新班表」：晚幾天才看到也不會搞混）；沒有管理員時給上傳者的「📅 選這張的日期」（放在別的回覆前面時，回覆下方的快速按鈕只會是那則回覆自己的，所以改成卡片上可以點的一格）；私訊照片辨識太久時的結果（見下面）。
- **什麼時候送到**：那個人下一次收到任何回覆時（打指令、按選單、查班表都算）。收件匣**從最舊的開始**放在回覆最前面，一組（例如回報卡片和它的原圖）一定一起送、不會拆開。LINE 一次回覆最多 5 則：回覆本身的訊息一則都不會少、一定在最後，下方的快速按鈕也照樣在；放不下的那一組和它後面的留到下一次。還有沒送的時，有空間就多一行「📬 還有 N 則訊息，傳「收件匣」查看。」（管理員是「傳「收件匣」或按選單「辨識回報」查看」）。回覆真的送出去才算看過，回覆失敗就下次再送。同一個人同時有兩個事件（例如連點兩下按鈕）時，收件匣的每一組只會跟著其中一個回覆送出（送之前先標記起來，回覆失敗再放回去），不會收到兩次。收件匣裡萬一有一則 LINE 不收的訊息，那次回覆會改成只送回覆本身，不會因此每次回覆都失敗；同一組被拒收兩次（`MAIL_TRIES`）就略過，記錄會印出來。
- **管理員回覆裡的順序**：最前面是意見回饋和人流資料的摘要（各一則，見「意見回饋」），接著是收件匣，最後是回覆本身。摘要一則就包含全部，收件匣的一組可能佔好幾則，而且隨時可以用 `收件匣` 拿到，所以摘要優先。
- **`收件匣`**（也可以打 `辨識回報`、`我的訊息`；**管理員選單「管理」那排新增的「辨識回報」按鈕**送的就是它）：只回收件匣裡還沒看過的，最舊的先，一次最多 5 則；還有更多時，最後一則寫「📬 還有 N 則訊息，再傳「收件匣」繼續看。」，下方有「📬 繼續看」按鈕（N 是組數，一組可能是好幾則，所以可能要再按幾次）。沒有時回「📭 沒有新的訊息。」，管理員多一句「群組有新的班表照片或航班人數訊息時，辨識回報會放在這裡。」這則回覆只放收件匣，意見回饋的摘要等下一次回覆。任何人都能用，名冊守門員也放行（上傳者收到的提醒也在收件匣裡）。
- 每人最多留 30 組還沒看的（`MAILBOX_KEEP`），再多就刪掉最舊的，記錄會印出來；已經送出的一週後從資料庫清掉。
- **日期讀不到的群組班表不再扣著**：不推播就沒辦法馬上問管理員，所以照「所有管理員都收不到私訊」時的做法直接發布，顯示「日期未辨識」；管理員收件匣裡的辨識回報有「📅 日期不對？點這裡改這張的日期」，看到時用它補上日期（推播開啟時的做法見「管理員：日期讀不到時先確認再通知」）。
- **意見回饋**不再每天推播一次，只跟著管理員的回覆送出（見「意見回饋」）。
- **自動通知一律關閉**，不管 `LINE_V2_NOTIFY` 寫什麼（不然每個人的收件匣都會塞滿新班表）；啟動記錄會說明，`通知 開` 回覆「自動通知要用每月的推播額度，機器人目前設定成不推播（省下額度），所以自動通知是關的。」
- **私訊傳的照片**：辨識完就直接回覆（免費）。回覆時限（`reply_window`，50 秒，從 LINE 送出這個事件的時間算起，排隊等處理的時間也算在內）結束前 5 秒還沒辨識完，先回一句「⏳ 還在辨識，好了之後傳任何字給我（或按「我的班表」）就會看到結果。」，辨識結果放進收件匣；同一個回覆 token 只會用一次。其他查詢超過回覆時限時一樣先試著回覆（token 可能還有效），回覆失敗才放進收件匣。
- **姓名申請**：申請卡片放進管理員的收件匣，申請人收到「有結果之後，你下次傳訊息給我就會看到」；管理員按同意／不同意後，回覆寫「對方下次傳訊息給我時就會看到」。同一人 12 小時內再申請不會再放一張卡片（免得管理員的收件匣被塞滿，擠掉辨識回報）。
- **改回推播**：在 `.env` 設定 `LINE_V2_PUSH=1` 後重啟（`./linebot_v2_restart.sh`），所有行為回到下面各節寫的推播方式，收件匣裡還沒送出的照樣會跟著回覆送出。啟動記錄會印出「推播：開／關」。
- 本機模擬器同樣預設不推播，`python -m all_staff.cli line-sim --push` 可模擬推播。
- **部署這一版之後，要再執行一次 `python -m all_staff.cli line-menu`**（先部署並重啟伺服器，再上傳選單），管理員選單才會有「辨識回報」按鈕（見「1:1 聊天室下方的選單」）；還沒重新上傳之前，管理員打 `收件匣` 一樣可以用。

下面各節寫的「私訊」「推播」，在預設的不推播模式下都是放進收件匣、跟著下一次回覆送出，不用額度。

### 自動通知（預設關閉）

群組有新班表時，機器人**預設不會私訊任何人**：照片照常辨識、存成全隊班表，同仁自己按選單的「我的班表」查看。
原因是訊息額度：私訊是 push，以收件人數計（每位開通知的人、每張班表各 1 則），免費的輕用量方案每月只有 200 則；
使用者按選單、傳文字或傳照片得到的回覆走 Reply API，不計額度。

- 開啟：在 `.env` 設定 `LINE_V2_PUSH=1` 和 `LINE_V2_NOTIFY=1` 後重啟（`./linebot_v2_restart.sh`）；自動通知就是推播，預設不推播時 `LINE_V2_NOTIFY=1` 不會生效。啟動記錄會印出「自動通知：開／關」。
- 資料庫裡誰開過通知的紀錄（`users.notify`）不會被清掉；重新開啟後，原本開通知的人直接恢復。
- 關閉時，`通知 開` 不寫入任何紀錄，只回一句說明：預設不推播時是「自動通知要用每月的推播額度，機器人目前設定成不推播（省下額度），所以自動通知是關的。」（見「不推播（預設）」），推播開啟（`LINE_V2_PUSH=1`）但沒設 `LINE_V2_NOTIFY=1` 時是「自動通知目前停用」；`通知 關` 照常。說明卡、`我的設定`、登記姓名的回覆都不再提到通知。
- 預設不推播時下面這些都不用額度，放進收件匣（見上一節）。推播開啟（`LINE_V2_PUSH=1`）時，自動通知關閉也仍會用到額度的：設定管理員後，**群組每一張照片的辨識回報**（每張照片、每位管理員各 1 則，附的勤務人員原圖在同一次推播裡，不另外算，見「管理員：群組照片的辨識回報」）、
  **群組每一則航班人數訊息的讀取結果**（每則訊息、每位管理員各 1 則，見「管理員：群組人流資料的讀取結果」），
  以及零星幾種（每次 1 則，給管理員的是每位 1 則）：私訊照片辨識超過 50 秒、群組照片無法辨識（私訊上傳者）、
  班表日期讀不到（私訊管理員；沒設管理員時私訊上傳者）、意見回饋（每天最多推播管理員一次，見「意見回饋」）、姓名申請（見「姓名鎖定與改名申請」）。
- 不用額度的：所有回覆，包括推播沒送到任何管理員時，留到管理員下一次回覆才一起送出的人流資料讀取結果（見「管理員：群組人流資料的讀取結果」）。
- 本機模擬器同樣預設關閉，`python -m all_staff.cli line-sim --push --notify` 可模擬開啟。

以下提到「通知已開通知的人」的行為，都只在自動通知開啟時發生。

### 同仁私訊流程

```text
設定 王小明
```

同仁一律登記**姓名**。數字代號每天輪動，機器人會讀班表下方的「服勤人員姓名代碼對照表」，
找出每個姓名當天的代號；中文代號（役男）與英文代號 A–N 是固定的，直接使用固定代號名冊。私訊與「我的班表」都會套用這些對應。無需先在群組發言。自動通知開啟時，每個人的通知預設關閉，必須先登記姓名再輸入 `通知 開`。
登記成功的回覆是「已登記：王小明」接著**和 `我的班表` 一模一樣的卡片**（下個小時、今天、明天；設定 `LINE_V2_PUBLIC_BASE_URL` 時再附藍框標示圖），一樣先看今天的班表，明天的已經上傳也不會跳過今天；還沒有任何班表時只回一句說明。登記的姓名要在名冊上，否則不登記、也看不到任何資訊（見「名冊守門員」）。姓名登記後就鎖住了，要改得經管理員同意（見「姓名鎖定與改名申請」）。
群組新照片辨識成功後，只私訊已開通知的人，包含照片上傳者；設定 `LINE_V2_PUBLIC_BASE_URL` 後，推播會先送整張未標記的原始班表照片（另產生縮圖供 LINE 預覽），再送個人的**單日班表卡片**（見下方「單日班表卡片」：漸層區最上面寫「📌 新班表」或「🔄 班表更新」，更新版多一格「🔁 你的勤務與上一版不同」）及勤務標示圖。姓名未配對時也會先送原圖，再提示補登；原圖無法產生時仍會送文字或個人卡片。同日更新版同樣先送該更新版原圖。
姓名對照表沒辨識出某人時，那個人會收到提醒，回覆 `我是 72`（當天的代號）就會把這張班表的 72 對應給他；`我是 72 9/30` 可指定日期。
群組裡只處理兩種訊息：班表照片，以及有離站／出境人數的航班人數訊息；其他文字一律不處理，群組裡也從不回覆。每一張照片的結果（辨識成功、失敗，或看起來不是班表而略過）都會給管理員一張回報卡片（預設放進管理員的收件匣；見「管理員：群組照片的辨識回報」）。不像班表的照片（截圖、合照等）只有傳的人以前上傳過班表時才私訊提醒（可能是班表拍壞了），其他人傳的不私訊。
看起來是班表但辨識失敗時私訊上傳者（設定管理員後也回報給管理員；管理員自己傳的只收回報），保留原班表。日期讀不到時也會私訊上傳者一句提醒，下方附「📅 選這張的日期」：LINE 的日期選擇器，綁定**那一張**照片，選了就改那一張（見「日期不對時：看得到、改得到」）；按鈕不見了也可以打 `日期 月/日`，更正自己最後上傳的班表日期，沒有上傳紀錄時更正最新可見的班表。日期更正不會再次推播。設定管理員後，日期讀不到與群組班表的日期更正都改由管理員處理（見「管理員：日期讀不到時先確認再通知」）。

- `我的班表`（選單「班表」那一整排的大按鈕；以前的 `今天班表`、`明天班表`、`下個時段` 三個按鈕合併成這一個，這三個字和 `班表`、`我的`、`下個小時` 照樣可以打，都是這張卡片）：一張卡片看完今天和明天，以台灣現在時間與日期為準。
  - 最上面的漸層區寫姓名、今天日期與現在時間，下面一大行明確寫出**下個小時**：「⏭️ 下個小時 11–12」＋「國際線」（即使和現在做同樣的工作也照樣寫）；下個小時沒有勤務時寫「沒有勤務」並接一行「👉 下一段 13–15：國內一線」；正在上班時多一行「▶️ 現在 10–11：國際線」，這時下個小時沒勤務就寫「休息 ☕」，今天最後一段就寫「下班 🎉」。今天的勤務都結束了、或已經過了 23 點（下個小時是明天的 00–01），就改看明天：「👉 明天第一段 05–07：國際線」、「💤 明天輪休」或「🌙 明天的班表還沒上傳」。
  - 「☀️ 今天」：每一段勤務一個圓角方塊（時段、勤務、幾小時），旁邊寫當天代號和共幾小時；正在做的那段加橘色外框和「▶ 現在」，做完的變灰並打「✓」，下一段標「⏭️ 下一段」，中間空檔寫「☕ 08–10 休息 2 小時」，信心較低的勤務標「？」；卡片下方有這些記號的說明，不只靠顏色。
  - 「🌙 明天」：每段一行（時段、勤務、幾小時）；明天的班表還沒上傳時是淡淡的「明天的班表還沒上傳」。
  - 沒有勤務的日子寫原因：班表右下角記載輪休（💤）或假別（🌴，例如「今天事假」；假別沒讀出來就寫「今天請假」）；休假區沒有辨識出來時，只寫「今天沒有排勤務」並請對照原圖，不會亂猜是輪休還是請假。那天的班表還沒上傳就寫「還沒上傳」（今天和明天都沒有時，提供「👉 先看最新的一張」）；姓名對照表上沒有自己時，每一天各自寫「找不到你」並提示傳 `我是 代號 10/8`（點一下會打開鍵盤帶入「我是 10/8 」，接著打代號就好；日期寫在前面或後面都可以，有日期才會記在那一天的班表，而不是最新的明天班表）。
  - 設定 `LINE_V2_PUBLIC_BASE_URL` 後，卡片下方附一張藍框標示圖：今天還有勤務就是今天的，否則是明天的。回覆下方**不會跳出其他選項**；要看某一天的完整個人卡片就直接輸入日期（`今天`、`明天`、`10/9`），找不到自己時點卡片上的「我是 代號」那一格。
  - 一張卡片（giga），不用左右滑動；就算兩天的每個小時都換工作，也在 LINE 的大小限制內（太大時今天改成一段一行）。需先設定姓名。
- `9/30`：直接輸入日期查看自己那天的單日班表卡片，也可用 今天／明天／昨天；同一天重新上傳時以最後一張為準。卡片下方「📆 其他日期」是最近幾天有班表的日期方塊，點一下就等於打了那個日期。
- `查 72`／`查 王小明`（可加日期）：看別人的勤務，也是單日班表卡片。查姓名時「📆 其他日期」點了是 `查 王小明 10/11`；只查到代號、沒有姓名時不提供（代號每天換，別天的 72 是別人）。
- 「查詢人員」按鈕：打開鍵盤並預填 `查 `，接著輸入代號或完整姓名。未附日期的查詢會沿用最近 12 小時正在看的班表；若無瀏覽紀錄，優先查今天，今天沒有才查明天。原始班表照片、時段、工作與人員卡片都會更新目前選定的班表；明確輸入日期會切換日期。查詢後下方只提供「查其他人」、「前一人」或「後一人」（查自己的班表時另有「本月統計」），不再顯示「勤務人員」、「休假人員」；前後依當張班表的代號順序，跳過沒有姓名也沒有勤務的代號。按鈕固定在正在看的班表，後續上傳新照片不會改變舊按鈕查詢的日期。「查其他人」預填正在看的日期。
- 勤務代號 `1/11`、`2/22`、`3/33` 會以字形逐字複核，只有每個字都達到信心門檻才採用新讀值，並保存修正前的文字。沿用現有模型，沒有重新訓練權重。舊班表查詢時會補讀保存的勤務格一次；個人標示圖使用新網址，避免 LINE 繼續顯示舊圖。缺少保存圖片時仍可查看舊結果，但會提醒代號尚未複核。多次姓名 OCR 都將「姍」讀成「姻」時，必須至少兩次能精確對上名冊，且沒有另一個明確姓名，才補回姓名；不改寫名冊內實際含「姻」的姓名。個人沒有勤務且右下角有輪休或請假記載時，會顯示原表的分類。
- `查看時段`：一張卡片看完整天，不用左右滑動。上半是「✈️ 國際線」（c02–c16，紅線左側），下半是「🏠 國內線」（c17–c30，A1 左側），05–06 到 23–24 每小時一格、一排五格；格子寫著時段和那個小時在那一區上班的人數（同一人同一小時兩項勤務只算一次），點一格就列出那些人，依勤務分組。顏色越深人越多：國際藍色、國內綠色，各以當天人最多的時段為最深，四段深淺，沒有人的時段是白底外框；區域標題旁寫著人最多的時段。看的是今天的班表時，現在的時段加橘色外框並寫「現在」，已經過去的時段顏色變淡、字變灰；卡片下方有顏色說明。舊卡片上的時段按鈕照樣可以用。也可直接傳 `10-11 國際`、`7 國內`、`10-11 國內 9/30`。A1 以右的欄位（A1站、A1A3站帶勤、A1A3站、內機、內部管理、全區帶勤）不列入這個查詢，其他查詢都看得到；「換時段」沿用正在查的班表日期。設定 `LINE_V2_PUBLIC_BASE_URL` 後，查詢會附上工作內容標頭與單小時原圖：只顯示所選區域及左側時段欄，可點開放大。舊班表只要保存了校正照片與格線資料，也能產生對照圖，不用重新上傳。
- `查看工作`：一張卡片列出班表上實際辨識到的每項工作，不用左右滑動。工作依第一欄所在位置分成「✈️ 國際」（c02–c16）、「🏠 國內」（c17–c30）、「🧩 其他」（A1 以右）三區，每項工作是一個方塊，寫著工作名稱和整天輪到這項工作的人數，一排三個；名稱太長時字略縮小，不會被切掉；標頭讀不出來的工作以欄號表示（「第15欄（未辨識）」）。點方塊就看該工作整天的名單：一張卡片，每個有人上班的小時一列，左邊是時段，右邊一排兩人寫代號（粗體）與姓名；姓名未配對時只寫代號，低信心格標「？」。看的是今天的班表時，現在的時段加橘色外框並寫「現在」。舊卡片上的「查看」按鈕照樣可以用。可用 `查看工作 10/4` 指定日期；今天與明天都有班表時，也可在選單或工作名單下方切換日期。名單卡片一般在 25 KB 以內；只有在一項四欄寬的工作每格都讀到兩個代號、而且整天都有人時，才會把時段分成兩張左右滑動。
  - **原圖對照**：設定 `LINE_V2_PUBLIC_BASE_URL` 後，名單下方附這項工作的原圖裁切（卡片註明「下方為這項工作的原圖，可點開放大」），切換鍵移到圖片下方。圖上只有這項工作的欄位與左側時段欄：最上方是原表的工作標頭，下面從第一個到最後一個有人上班的小時逐列排下來，工作格以藍框標出；每一欄、每一小時各自拉正，照片略彎也不會歪。大多數工作只有一欄，一整天排成一長條在手機上太細，這時會分成兩到三段左右並排（每段都有標頭），選最接近直拿手機畫面比例的排法。和 `查看時段` 的單小時原圖用同一套格線，第一次查詢時產生並存在 `runs/<id>/works/`；舊班表沒有存標頭位置時會重新定位一次，不用重新上傳。裁切失敗或沒有校正照片時只回名單。
- `勤務人員`：一張卡片列出當天全部的代號與姓名，不用左右滑動。上方寫日期與「姓名已配對 N 人」，下面分「🔢 數字代號」「🔤 英文代號」「🎖️ 中文代號」三區（區名旁寫人數和未配對人數），依代號順序一排三人，代號粗體、後面接姓名，隔行淡底方便對齊。姓名未配對的代號後面只有淡灰色的「—」，不按名冊順序猜代號；當天沒有這個人的代號（見「管理員：群組照片的辨識回報」）寫淡灰色的「空白」（姓名欄空白）、「沒設定」（固定代號沒有設定）或「表上沒有」（班表上沒有這個代號），不算未配對，卡片下方另有一句列出；卡片最下方用一句話寫出幾人姓名未辨識、請看下方原圖。包含輪休與請假人員，姓名後面標 💤（輪休）或 📝（請假），並附圖例。卡片下方附班表「服勤人員姓名代碼對照表」原圖裁切供核對；「🖼️ 查看整張班表」是卡片底部可點的一列，不會因手機太窄被切字，點了直接回傳原始照片。全隊 78 人的一天約 20 KB，代號 1–84、A–N、甲–酉全部 118 個也放得進一張；只有在名字都很長、又每人都標了休假時（或姓名一個都沒讀到、固定代號也都沒設定時），英文與中文代號才會移到第二張。可用 `勤務人員 9/30` 查指定日期；回覆下方提供「查詢人員、查看時段、休假人員」，沿用正在看的日期，即使後續有新上傳也不會換班表。原圖無法裁切時仍顯示文字、查詢選項與「查看整張班表」。
- `休假人員`：按所選日期班表右下角的記載，一張卡片顯示「💤 輪休人員」與「📝 請假人員」，不用左右滑動，另附該區塊原圖核對。輪休人員依代號排序、一排三人（代號粗體加姓名），不再照照片的左、中、右三欄排列；請假人員每人一列，左邊是代號，中間是姓名（有事由時寫在姓名下方），右邊是假別（補休、休假、公假、退伍……各有淡色底）。辨識不清的地方不再一格一格寫「代號？」：姓名沒讀出來時代號後面是淡灰色的「（未辨識）」，代號沒讀出來的格子合成一行「🔍 另有 3 格看不清楚，請看下方原圖」，假別沒讀出來寫「假別未辨識」；只讀到姓名、沒讀到代號的請假人員代號位置是「—」。整個休假區塊都沒讀出來時，卡片寫「休假區塊尚未辨識」並請對照原圖，不會把沒有勤務的人推定為休假。請假假別會從保留原筆畫的格子再讀，支援身心調適假、災防假等較長假別。可用 `休假人員 9/30` 查指定日期，也可單獨查 `輪休人員` 或 `請假人員`（卡片只顯示那一部分）。回覆中的人員按鈕沿用正在查的班表。代號對應使用當天姓名表。舊班表會在第一次查詢時補讀保存的照片並快取，不需重新上傳；無法裁切時可按「查看整張班表」取得原始照片核對。輪休 42 格、請假 22 列全部填滿也放得進一張；要是每列還有很長的事由，輪休與請假才分成兩張。
- `人流預測`：依群組每天貼出的航班人數訊息，預估當天每個小時國際線、國內線安檢忙不忙。一張卡片列出有旅客的時段，國際、國內各標「超忙／忙／正常／閒／超閒」五級，上方列出各自最忙的時段（忙與超忙），並框出現在的小時。預設看今天，今天沒有資料時看明天；也可用 `人流預測 10/7`、`人流預測 明天` 指定日期，今天與明天都有資料時可在卡片下方切換。
  - 旅客不是在起飛那個小時才過安檢，所以先把每小時的出境／離站人數往前攤開：國際為同一小時 6%、前一小時 44%、前兩小時 43%、前三小時 7%；國內全部算在起飛前一小時（例如 10–11 時起飛的國內旅客，算在 9–10 時過安檢）。
  - 再除以當天班表該小時在「國際線」／「國內線一線」上班的人數（二線、備勤不算），和當天最忙三個小時的平均比較，分五級：達 95% 標「超忙」、達 75% 標「忙」、達 40% 標「正常」、達 20% 標「閒」，不到 20% 標「超閒」；每小時不到 60 人的時段最多標「閒」。等級只和當天自己比，不和其他日子比，所以平常日也會有「超忙」的時段。當天班表還沒上線時只看人流。
  - 攤開的比例是推估值，沒有實測校正（沒有每小時實際過檢人數的紀錄），所以卡片只顯示等級，不顯示預估人數。比例與門檻在 `all_staff/passenger_flow.py` 開頭。
- 航班人數訊息（開頭是 `2026年10月06日`，接著 `【國內 – 離站】`、`6-7時：2架74人`…）貼在機器人所在的群組時會靜默記下，當作全隊那一天的資料，同一天以最晚傳送的一則為準。只有到站／入境、沒有離站／出境的訊息不記錄（預估只用離站人數），私訊貼的也一樣。也可以把整則訊息私訊貼給機器人，會直接回覆預估；私訊貼的只有自己查得到，不會改變群組的資料。設定管理員後，群組裡每一則航班人數訊息有沒有記下，都會給每位管理員一張卡片（預設放進收件匣，不用額度；推播開啟時馬上推播，計額度；見「管理員：群組人流資料的讀取結果」）。
- `本月統計`（選單「更多」第一顆）：自己這個月到今天為止的**排定時數**、上班天數與平均，畫成圖表：上方三格數字，「🗓️ 班表月曆」把整個月排成月曆，「🍰 各地點時數」每個地點一條橫條，最久的排最前面、以最久的為滿格。粉色系、圓角、表情符號，Flex 卡片直接畫，不用另外產生圖片。
  - **只看得到這個月**。`上月統計`、`9月統計` 和舊卡片上的「看 9 月」按鈕都會回覆「統計只看得到這個月的喔」並顯示本月。卡片下方是「我的班表／查看工作／💰 加班結算」；這個月有加班時，卡片上方多一行「其中加班 N 小時」，點了就是加班結算。
  - **🗓️ 班表月曆**（取代原本的「📊 每天的時數」長條圖，每天的資訊都還在）：一週一排、從星期日開始（日 一 二 三 四 五 六），每天一格，格子裡是日期和一個小標記：上班的日子寫排定時數（`8h`，超過 8 小時的日子粉色較深）、`💤` 輪休、`🌴` 請假（含補休、身心調適假等假別）、`🍃` 班表上沒有你的勤務、`❓` 有班表但姓名沒配到、`⏳` 舊班表還在重讀；底色也分上班（粉）、休假（紫）、沒算到（杏），下方的圖例只列出月曆上有出現的種類。沒有班表的日子是灰色、不能點（班表資料讀不出來的日子也是灰色，標 `⚠️`）；還沒到的日子只有淡淡的日期；今天有深粉色外框。每一格（連同星期列和月初、月底湊不滿一週的空格）都是固定的同一個寬度（`CALENDAR_CELL`，13.5%），每排平均分開：只靠 flex 的話，LINE App 會依格子裡的內容分配寬度，有空格的第一排、最後一排，或有 `10h` 這種比較寬標記的那週，日期會比上下週寬一點，欄位就對不齊。格子只有上下留白，左右不留，免得留白算在寬度之外、整排超出框。
  - **點有顏色的日期**就查那一天：先回整張原圖班表（有設定 `LINE_V2_PUBLIC_BASE_URL` 時），再回自己當天的單日班表卡片和藍框標示圖，最後**再回一次那個月的月曆**（標題寫「剛看完 10/8 的班表，點其他日期繼續看 🐰」），不用退回本月統計就能接著點別天，最多四則訊息；這時單日班表卡片不放「📆 其他日期」（月曆就是用來選日期的），「查其他人／前一人／後一人／本月統計」按鈕在月曆下方。這個月的月曆到今天為止、今天有外框，從 11 月起一樣有「◀ 10 月的班表」；點的是上個月的日期，就回上個月整個月的月曆。勤務卡片已經附原圖，就不再放「查看整張班表」按鈕。那張照片的日期是後來設定的（照片表頭印的是別天）時，卡片漸層區會寫「📅 這張的日期是後來設定的（照片上讀到 9/29）」，原圖表頭和點的日期對不上就有解釋（見「日期不對時：看得到、改得到」）；管理員的卡片照樣有「📅 改這張的日期」。那天的姓名對照表找不到自己時，照樣先附原圖，再回「請傳『我是 你的代號 10/5』」的補登說明，接著是月曆；班表資料讀不出來的日子也是原圖、一句說明，再接月曆。用的是那一天**最新的一張**班表（和統計、`我的班表 10/5` 相同），只會是群組的班表或自己私訊上傳的，看不到別人私訊的班表。之後直接 `查 72` 也會查同一天。
  - 附在後面的月曆**不會**重讀舊版讀法存下的班表（重讀一張要十幾秒，回覆會趕不上），那些日子照樣標 `⏳`、可以點，回本月統計就會接著重讀。點的那天本身如果重讀了很久、LINE 回覆時限（`reply_window`）只剩不到 10 秒，就不附月曆，只回那天的班表，一樣用免費的回覆，不會為了月曆改用 push。舊卡片上兩個月以前的日期也不附月曆（月曆只看得到這個月和上個月）。
  - 月曆**從 2026 年 10 月開始**（`CALENDAR_START`），不會出現更早的月份或日期。從 11 月起，月曆下方多一格「◀ 10 月的班表」，點了會另外回一張只有上個月月曆的卡片（一樣可以點日期查班表，下方「📊 回到本月統計」），**不會**有上個月的時數統計；只能往前看一個月。還沒到的日期、10 月以前的日期或更早的月份（例如舊卡片的按鈕）會用一句話說明，格式不對的按鈕資料直接忽略。月曆按鈕的資料是 `cal|2026-10-05`（某一天）和 `cal|2026-10`（上個月）。
  - 整個月 31 天都能點、橫跨六週，再加上最長的備註和九個地點，整張卡片約 27 KB，仍在 LINE 一張 30 KB 的上限內（`FLEX_BUBBLE_LIMIT` 28 KB）。
  - 算法：該月每一天取當天最新的一張班表（和其他查詢相同），用姓名對照表找出自己當天的代號，班表上有勤務的每一個小時列算 1 小時；同一小時排了兩個工作時仍算 1 小時，兩個地點各算 0.5。明天的班表即使已上線也不算進「本月」。
  - **這是班表上排定的時數，不是出勤紀錄**：臨時換班沒有重貼班表就不會反映。
  - 卡片下方會列出總數沒有涵蓋的日子：沒有班表的日期、有班表但姓名沒配到的日期（本人傳 `我是 代號 10/5` 補登後就會算進去）、班表上沒有勤務的日期（對照表有記載時標「輪休」或假別）、信心較低的小時數，以及仍是舊版讀法（最右四欄沒讀到、啟動時重讀又失敗）的日期。日期未辨識的班表在補上日期之前不屬於任何一天。

- `加班`／`月底結算`（也可以打 `加班費`、`加班時數`、`結算`、`本月結算`，或點本月統計卡片下方的「💰 加班結算」）：這個月的加班時數與加班費試算。和本月統計一樣**只看這個月、算到今天**，所以月底最後一天查就是整個月的結算；`上月結算` 會說明只看得到這個月並顯示本月。

- `解除`：取消姓名登記並關閉通知。

查看時段人員使用 Flex 卡片：漸層標頭寫時段與區域（例如「✈️ 10–11 國際線」）、班表日期與「共 N 人」；每項勤務一個圓角列，左邊是勤務名稱與人數，右邊每人一行，代號加粗、後面接姓名，信心較低的標「？」；辨識提醒與原圖對照仍保留。
`查看時段`、`查看工作`、`勤務人員`、`休假人員`（含單獨的 `輪休人員`、`請假人員`）預設先顯示今天的班表；如果今天尚未上線，才顯示明天或最近一張。有今天與明天兩張時，回覆下方會出現「今天／明天」切換鍵，切換時保留目前查詢類型；單小時查詢會保留同一時段與國際／國內選擇，查看工作會保留所選的工作。日期鍵綁定各自的班表照片，之後上傳新班表也不會讓舊按鈕跳錯照片。這些指令都能附日期查其他日。

私訊 `用法說明`（或 `說明`）會顯示四張可左右滑動的卡片，依下方選單的「班表、查詢、人員、更多」排列，逐一解釋十個按鈕；每張卡片採用與選單分類相同的顏色。選單上沒有「用法說明」按鈕，所以最後一張卡片最下面寫著「想再看這四張說明卡，隨時傳「說明」。」補代號、指定日期、更正日期等文字操作放在 `進階說明`，可點最後一張卡片下方的按鈕開啟。
休假區塊第一次查詢需要補讀照片，期間會顯示處理中的動畫；若超過 LINE 回覆時限，推播開啟時改以私訊送出完成的清單與原圖，預設不推播時仍先試著回覆，回覆失敗就放進收件匣。結果及裁切圖會快取，後續查詢不再重跑 OCR。

#### 單日班表卡片

一個人在一天的班表：打日期（`10/1`、`今天`、`明天`）、`查 72`／`查 姓名`、`我的班表` 卡片上的「👉 先看最新的一張」、班表月曆點日期、新班表通知，都是這張卡片（`duty_card`），和 `我的班表` 同一套樣式，一張 giga 卡片：

- **漸層區**（深藍到藍綠）：最上面一小行寫「📋 我的班表」、「🔎 同仁班表」，或通知的「📌 新班表」／「🔄 班表更新」；接著大字「林小明（72）」（沒有姓名時「代號 72」）、日期膠囊「📅 10/8（四）・今天」（今天／明天／昨天才加），有勤務時再三格「05:00 上班」「18:00 下班」「9 小時 排定時數」。通知的更新版多一格「🔁 你的勤務與上一版不同」。日期是後來設定的時，最下面一行淡字「📅 這張的日期是後來設定的（照片上讀到 9/29）」或「（照片上沒有讀到日期）」。
- **勤務**：每一段連續的勤務一個圓角方塊（時段、勤務、幾小時），段與段之間寫「☕ 08–10 休息 2 小時」；同一小時兩項勤務寫成「國際線／國際備勤」，只算 1 小時；信心較低的標橘色「？」。看的是**今天**（台灣時間）的班表時，正在做的那段加橘色外框和「▶ 現在」，做完的變灰並打「✓」，下一段標「⏭️ 下一段」，正在休息就是那行「☕」寫「▶ 現在」；其他日子全部是白色方塊。下方有記號的說明。
- **沒有勤務**的日子是一格安靜的說明，和 `我的班表` 的寫法相同：「💤 今天輪休」、「🌴 這天事假」（假別沒讀出來寫「請假」）、在姓名對照表上但沒有勤務的「🍃 這天沒有排勤務」（休假區沒辨識出來時請對照原圖，不亂猜），以及代號根本不在這張班表上的「🔍 這張班表上沒有辨識到代號 8」。查自己寫「你」，查別人寫對方的姓名。
- 舊班表代號尚未複核的提醒（`1／11、2／22、3／33 請對照原圖`）是一格淡橘色；有藍框標示圖時寫「📷 下方是標示圖：藍框是勤務格」。
- **📆 其他日期**：最近六天有班表的日期方塊（由舊到新，一排三個，今天那格淡藍色），點了等於打那個日期（查別人時是 `查 姓名 日期`）。從班表月曆點日期時沒有這一區：回覆最後會再附一次月曆，直接在月曆上點下一天。
- **管理員**看到的卡片最下面多一格「📅 改這張的日期」（只改這一張｜管理員才看得到），點了打開 LINE 的日期選擇器，改的是這張卡片的這一張照片；其他人沒有這一格，按舊卡片也沒有作用。
- 設定 `LINE_V2_PUBLIC_BASE_URL` 時卡片底部有「🖼️ 查看整張班表」，點了直接回傳原始照片；卡片下方照樣附藍框標示圖。回覆下方的「查其他人／前一人／後一人／本月統計」不變（從班表月曆點日期時在最後的月曆下方）。
- 通知預覽與 altText 仍是「林小明（72）　10/1（四）」接著各段勤務的文字，搜尋得到。一天 19 個小時都換工作、名字又長、日期又多時也在一張卡片內（約 20 KB）；萬一超過 25 KB，勤務改成一段一行。
- 姓名對照表上找不到自己時不是卡片，照舊回「請傳『我是 你的代號 10/5』」的補登說明。

登記姓名後顯示的是 `我的班表` 卡片（今天和明天），不是這張。

#### 意見回饋

同仁私訊 `意見 內容`（也接受 `回饋`、`建議`、`回報` 開頭），機器人會：

1. 把整段文字原樣存進資料庫（`feedback` 表），連同登記姓名、LINE 顯示名稱、時間，以及對方最近 12 小時查看的是哪一張班表。回饋是**具名**的，回覆會告訴對方「會連同你的姓名交給管理員」。
2. 回覆對方「收到了」（Reply，不計額度）。
3. 交給 `LINE_V2_ADMIN_USER_IDS` 的管理員：預設不推播，在管理員下一次對機器人傳訊息或按選單時，隨著那次回覆一起顯示（Reply，不計額度；不放進收件匣，見「不推播」）。推播開啟（`LINE_V2_PUSH=1`）時**每天最多推播一次**（台灣時間；一次把還沒看過的全部列出，每位管理員計 1 則額度），同一天之後進來的不再推播，一樣隨著回覆顯示；推播沒送到任何管理員（額度用完、沒加好友）不算用掉當天那一次。

管理員私訊 `意見列表` 可看最近 10 則（管理員的 `人員管理` 卡片上的「💬 意見列表」方塊送的就是它，方塊上寫著有幾則新的）；其他人輸入這個指令不會有作用，也不會被存成意見。
沒有設定管理員時意見仍會存下並回覆對方，但不會有人收到（啟動記錄與每次收到時都會提醒）。
每人 24 小時內最多 10 則，單則最多保留 1000 字；群組裡的訊息不會被當成意見；私訊傳圖片一律當作班表辨識，所以意見只收文字。

#### 查哪一張班表、日期與「我是」

- 每個人看得到的班表＝所有群組上傳的班表＋自己私訊傳的照片。`我的班表` 看今天和明天各自最新的那張；沒指定日期的 `我是 72` 用**班表日期最新**的那張（日期未辨識時以上傳日計）；同一天有多張時用傳送時間最晚的。所以舊班表後來又被貼出來，不會蓋過較新的日期；自己私訊傳了較新的班表，自己查得到，但不會通知別人、也不改變其他人看到的班表。
- `日期 月/日`（`月/日` 換成班表上印的日期）優先更正**你自己最後上傳**的那張，之後別人上傳群組照片不會改變這個目標；沒有上傳紀錄時才更正最新可見的班表。回覆會說明是哪一張；照片上原本辨識到的日期會保留，改錯了可以再改回來。打字沒有指明是哪一張照片，所以能用日期選擇器的地方都改用選擇器（見下一節）。說明和提示裡不再寫 `日期 10/1` 這種看起來像真日期的例子：有人照抄送出，就把最新那張照片改成 10/1。
- `我是 72` 套用在班表日期最新的那張（明天的已上傳時就是明天的），`我是 72 10/8` 指定日期；`我的班表` 卡片上找不到自己時，提示裡就帶著那一天的日期。如果那張的姓名對照表上 72 是別人，會拒絕並提醒確認日期；72 在那張沒有勤務也會提醒。

#### 日期不對時：看得到、改得到

曾經發生：在班表月曆點 10/1，回來的原圖表頭印著「2026年9月29日」。查詢用的是資料庫裡的班表日期（`rosters.roster_date`），所以那張 9/29 的照片當時的班表日期就是 10/1；表頭日期辨識會核對星期、只接受上傳日附近的日期，讀錯成 10/1 的機會很小，多半是有人設定的：照著提示打了 `日期 10/1`（以前的提示和說明就是這樣寫的，打字改的是最新那張照片），或管理員在詢問卡片上只能從上傳當天起三天裡選（舊班表後來重貼，真正的日期按不到）。照片上讀到的日期一直另外存在 `rosters.read_date`。

- **看得到**：班表日期不是照片上讀到的那天時（`read_date` 是空的，或和班表日期不同），單日班表卡片的漸層區會寫一行淡字「📅 這張的日期是後來設定的（照片上讀到 9/29）」或「（照片上沒有讀到日期）」；班表月曆點日期、打日期、`查 72`、通知都是這張卡片。`read_date` 欄位出現之前存的舊班表沒有這個欄位的值，改用辨識結果裡存的表頭日期比對，不會誤報。
- **管理員改得到**：在班表月曆點那天（或打那個日期、`查 姓名 日期`），卡片最下面「📅 改這張的日期」→ 在日期選擇器選正確的日期。改的就是這張卡片的這張照片（`redate|<run_id>`，和辨識回報卡片上的「📅 日期不對？點這裡改這張的日期」相同），不會改到別張；改日期不會再次通知。還在等日期的照片選了日期就等於按了詢問卡片上的日期（確認並通知）。管理員自己私訊傳的照片也能這樣改。其他人看不到這一格，按舊卡片也沒有作用。
- **沒有管理員時，上傳的人改得到**：群組照片的日期讀不到，上傳的人（要在名冊上，見「名冊守門員」）收到的不再是「請私訊『日期 10/1』」，而是一句提醒加上「📅 選這張的日期」日期選擇器，只能改**自己傳的那一張**。設定了管理員之後，上傳者的選擇器就不再有作用（日期歸管理員管）；其他任何人按了都沒有作用。
- **詢問卡片的「📅 其他日期」**：管理員收到的「⚠ 班表日期讀不到」卡片，在三個日期按鈕下面多一格「📅 其他日期」，打開日期選擇器可以選更早（或更晚）的任何一天，綁定那一張照片（`date|<run_id>|pick`，選的日期在 postback 的 `params.date`）；選了和按日期按鈕一樣：確認日期並通知。格式不對的日期、其他人按的都不理會。
- **可選的日期範圍**：這些日期選擇器只能選照片**上傳日前 60 天到後 21 天**（`PICK_WINDOW`；LINE 的選擇器本身就限制在這個範圍，伺服器也會再檢查），免得選錯年份（例如 2027-10-01）讓那張照片變成大家的「最新班表」。範圍外的日期直接忽略。
- 姓名對照表上沒有自己（或查的人）時，回覆是一段文字而不是卡片；那張照片的日期是後來設定的話，文字開頭一樣有「📅 這張的日期是後來設定的」那一行，管理員的回覆下方也有「📅 改這張的日期」。
- 打字的 `日期 月/日` 照樣可用（說明見上一節）。

#### 姓名鎖定與改名申請

`我的班表`、`本月統計`、`加班` 都依登記的姓名查，所以姓名登記後就**鎖住**，免得有人把姓名設成別人的來看別人的資料：

- **第一次登記**：還沒有人登記的姓名直接登記（回覆見上面的「同仁私訊流程」），回覆會提醒「登記後就不能自己改了；打錯字再傳 `設定 正確的姓名`」。要登記的姓名**已經有別的 LINE 帳號登記**時，不會直接登記，而是送出申請。**一個姓名只能登記在一個 LINE 帳號**：管理員同意這種申請，就是把姓名**轉給申請人**，原本登記的帳號會被解除、變成沒有登記姓名、看不到班表（申請卡片上的警告會寫明，同意後的回覆也會列出解除了誰；不會另外推播給被解除的人）。沒有管理員可以確認時，這種登記直接被拒絕（回覆請對方聯絡幹部解除原本的登記）；只有唯一的那位管理員自己登記別人已登記的姓名時會直接接手。名冊守門員開著時（見下一節），名冊上沒有的姓名一律不登記、也不送申請。
- **改名**：已經有姓名的人再傳 `設定 新姓名`（或 `綁定`／`登記`／`姓名`／`我是` 加姓名）不會改，而是送出申請，回覆「已經交給管理員確認，有結果會私訊通知你」（預設不推播時是「有結果之後，你下次傳訊息給我就會看到」），在那之前姓名不變。傳自己現在的姓名只會說「本來就是你登記的姓名」，不會送申請（有申請在等時順便取消）。
- **誰確認：只有管理員**（`LINE_V2_ADMIN_USER_IDS`）。幹部照樣管理名冊（`人員管理`），但不審姓名申請：不會收到申請卡片，按了以前留下的卡片也沒有反應，傳 `姓名申請` 只會看到自己的申請進度。設定裡重複的管理員只算一次，每人私訊一張可愛的申請卡片：粉紫色漸層標題（「🙋 姓名變更申請」或「🙋 姓名登記申請」）、申請人（登記的姓名和 LINE 名稱）、送出時間，「現在的姓名 ➜ 想改成」兩格，姓名已經有人用時多一格橘色提醒（有幾個帳號、各帳號的 LINE 名稱；一個姓名只能登記在一個 LINE 帳號：同意後姓名轉給申請人，原本的帳號會被解除、看不到班表；原本的帳號是幹部或管理員時，會另外寫明他解除後照樣看得到班表、可以管理人員），最下面兩個大方塊「✅ 同意」「❌ 不同意」（每個方塊只綁這一筆申請）。推播開啟時每人每筆 1 則 push 額度；預設不推播時卡片放進管理員的收件匣，不用額度。
- **先按的人決定**：同意就立刻改名，並私訊申請人「改名申請通過了」接著新姓名的 `我的班表` 卡片（預設不推播時只有那一句，放進收件匣）；不同意也私訊申請人（姓名維持原樣，或第一次登記就是還沒登記）。之後其他人（或同一人）再按，只會回覆「這筆姓名申請已經處理過了：誰在幾點同意／不同意了」，什麼都不改、也不會再通知。只有管理員按的才算，其他人（包括幹部）按了沒有反應；自己的申請要由其他管理員確認，卡片也不會送給自己。私訊不到申請人時，按的人會收到提醒，請另外告知申請人。
- **同意時姓名已經不在名冊上**（申請送出後被 `刪除人員`）：按「✅ 同意」不會改名，回覆「「陳小華」目前不在名冊上，所以這次沒有同意…申請還在等」，並附「➕ 加入名冊」按鈕（`新增人員 陳小華`）；加回名冊後再按一次同意才算，不然就按不同意。
- **一人一筆**：申請還在等時又申請別的姓名，新的取代舊的（回覆會說「之前申請的「王小明」已經取消」），舊卡片按下去會說已作廢，並附「📮 姓名申請」按鈕看最新的；再傳一次同一個姓名不會再推播。一個人的申請推播給管理員之後 12 小時內、還沒有人回覆時，再送的申請照樣存下，但**不再推播**（免得一直換姓名用光每月的訊息額度，或塞滿管理員的收件匣），回覆會請申請人等管理員在 `姓名申請` 看到；有人同意或不同意之後再送、或上一筆根本沒送到任何人時，照常推播。`解除` 會取消申請中的改名；解除後姓名鎖仍在，之後登記原本以外的姓名一樣要申請（卡片顯示「還沒登記 ➜ 新姓名」並註明之前登記過的姓名），登記回原本的姓名則直接恢復。
- **同意前再確認一次**：每張卡片的按鈕都記著卡片產生的時間。卡片產生之後，如果有別的 LINE 帳號登記了同一個姓名，按「✅ 同意」不會直接改，而是回一張附上警告的新卡片，在新卡片上再按一次才算；每位管理員手上的舊卡片都一樣要再確認。
- **查看等待中的申請**：管理員私訊 `姓名申請`（也可以 `改名申請`、`姓名審核`），一張卡片列出等待中的申請（最舊的先，一次最多 8 筆，其餘註明還有幾筆），每筆都有自己的同意／不同意方塊。管理員的 `我的設定` 與 `人員管理` 會顯示有幾筆在等（幹部的不會）。其他人（包括幹部）傳 `姓名申請` 會看到自己的申請進度或怎麼申請。
- 推播失敗（沒加好友、封鎖、額度用完）不影響申請：申請照樣存下，管理員可以用 `姓名申請` 查；一個人都沒送到時，申請人會被請去直接告訴管理員。
- **沒有設定管理員**（全新安裝，或只有幹部）時姓名不上鎖，維持舊行為：直接改名，並在記錄印出警告。唯一的管理員改自己的姓名也是直接改。**別人已登記的姓名除外**：沒有人可以確認時一律拒絕（請對方聯絡幹部用 `解除登記` 處理）；唯一的管理員登記別人已登記的姓名時直接接手，原本的帳號解除。
- **舊的申請卡片**：這個規則上線前推播出去的卡片上寫的是「原本的帳號不受影響」。在那種卡片上按「✅ 同意」不會直接轉移，機器人會先回一張寫明「原本的帳號會被解除」的新卡片，在新卡片上再按一次才算。
- **被解除的帳號**如果自己有申請還在等，那筆申請會改成「還沒登記（之前登記過某某）」，不再顯示它已經沒有的姓名。
- **幹部或管理員的姓名被轉走時**：幹部／管理員身分跟著 LINE 帳號，不跟著姓名，所以舊帳號仍然看得到班表、可以管理人員，回覆會特別提醒，並說明新帳號要另外 `新增幹部`。
- 申請存在 `data/line_v2/bot.sqlite3` 的 `name_requests` 表（狀態：pending／approved／refused／replaced／cancelled，以及誰、幾點處理）；`users.released_name` 記住 `解除` 前的姓名。舊資料庫啟動時自動加上。「一個姓名一個 LINE 帳號」另外加了 `users.name_at`（上次向 LINE 查顯示名稱的時間）、`meta` 表的 `one_name_since`，以及唯一索引 `users_staff_name`；啟動記錄出現「⚠ 有姓名同時登記在好幾個 LINE 帳號上…」表示資料庫裡還有舊的重複，索引先不建，等用 `解除登記` 留下一個之後、下次啟動才會建立。**要退回舊版程式前**，請先對資料庫執行 `drop index users_staff_name`，否則舊版在同名登記時會出錯。

#### 名冊守門員

只有**登記的姓名在名冊上**的同仁，才能在私訊看到隊上的任何資訊；以前加了好友、不登記（或隨便登記一個姓名）就能查班表，現在不行了。

- **名冊**＝幹部在 `人員管理` 維護的人員名冊（`data/line_v2/staff_names.txt`）加上固定代號的姓名（`fixed_staff_codes.json`）。幹部 `新增人員`／`刪除人員` 馬上生效。
- **誰放行**：管理員（`LINE_V2_ADMIN_USER_IDS`）和幹部永遠放行，不用登記；其他人要登記的姓名在名冊上才放行。
- **登記**（`設定`／`綁定`／`登記`／`姓名`／`我是` 加姓名，第一次登記和改名申請都一樣，管理員同意申請時也一樣）：名冊上沒有的姓名**一律不登記、不送申請、什麼都不改**，回覆「🙏 名冊上沒有「王大明」，所以沒有登記」，請對方確認有沒有打錯字；新進同仁先請幹部加入名冊（人員管理 → 新增人員），再傳一次 `設定 你的姓名`。回覆**不會列出或提示名冊上的任何姓名**（對方還沒放行，列出來等於洩漏名冊）；說明裡的例子一律用 `王小明`（`蕭志明` 是名冊上的真人，舊的例子已換掉）。名冊上、但已經有別的 LINE 帳號登記的姓名，照舊送給管理員確認。幹部和管理員本來就放行（沒登記姓名也能用人員管理），但登記的姓名一樣要在名冊上：打錯的姓名留在帳號上，哪天卸下幹部就會被擋在外面。
- **放行之前只能用**：上面的登記指令、`用法說明`／`進階說明`、`我的ID`、`意見 內容`、`我的設定`（顯示怎麼登記、申請進度）、加好友的歡迎卡片和它的「✏️ 點這裡，輸入我的姓名」。
- **其他一律回一張守門卡片**，什麼資訊都不給：查班表（`我的班表`、`今天`、`9/30`、`查 72`、`72`）、`查看時段`、`查看工作`、`勤務人員`、`休假人員`、`人流預測`（包括私訊貼航班人數訊息）、`本月統計`、`加班`、`時薪`、`通知`、`我是 72` 補代號、`日期` 更正、私訊傳的照片（不辨識）、圖文選單的每個按鈕，以及所有卡片按鈕（包括以前收到的舊卡片）。卡片是人員管理同款的漸層卡：「🔒 請先登記姓名」、為什麼（保護同仁的班表和個人資料）、一個大大的「✏️ 登記名冊上的姓名」方塊（點了打開鍵盤並帶入「設定 」），和新進同仁要先請幹部加入名冊的說明；有申請在等時會多一行「⏳ 你申請的「…」還在等管理員確認」。
- **姓名被移出名冊**（離隊、調走）：之前登記的人也會被擋下，守門卡片改成「🔒 姓名不在名冊上」，多一格「你登記的姓名「林小明」目前不在名冊上……如果你還在隊上，請聯絡幹部」，`我的設定` 也這樣說；重新加好友不會再說「歡迎回來」。加回名冊就恢復。名冊開始使用前就登記、但不在名冊上的人也一樣（幹部在 `人員名冊` 的「自己登記、不在名冊」可以一鍵加入）。
- **群組完全不變**：群組照片和航班人數訊息照樣安靜處理，管理員照樣收到辨識回報。**自動通知**（`LINE_V2_NOTIFY`）只私訊放行的人（還綁著舊代號的人也一樣），管理員確認日期時說的「已開通知的 N 人」也只算他們。
- **名冊是空的或找不到檔案**時守門員暫停（不然沒有人能登記），所有人照舊可以用，記錄印一次警告「名冊是空的」。完全沒有設定名冊檔（例如單元測試）時一樣不擋，也不印警告。
- 本機模擬器（`line-sim`）用 `configs/` 名冊的複本，所以模擬使用者要登記名冊上的姓名，或用 `--admin U_ming` 當管理員。

#### 管理員：群組照片的辨識回報

設定 `LINE_V2_ADMIN_USER_IDS` 後，群組裡**每一張照片**辨識完都會給每位管理員一張回報卡片，群組裡照樣不回覆。
預設不推播：卡片放進管理員的收件匣，等管理員下一次傳訊息、按選單（或按「辨識回報」）時一起送出，**不用額度**（見「不推播」）。
推播開啟（`LINE_V2_PUSH=1`）時這張卡片是 push，**會用掉每月的訊息額度**：每張照片、每位管理員各 1 則，例如 2 位管理員、群組一個月傳 30 張照片就是 60 則（免費的輕用量方案每月只有 200 則）。辨識成功時卡片下面附的勤務人員原圖和卡片是**同一次推播**，額度照樣只算 1 則。管理員自己傳訊息或按選單得到的回覆（Reply）不計額度。

- ✅ **群組班表辨識成功**：誰傳的、幾點傳的、班表日期（同一天的更新版或只存檔的舊版會註明），接著一格一行：
  - 👥 有勤務的代號數。
  - 👤 姓名配對，例如「53／54（1 個沒讀出來）」或「51／51，全部對到」：只算**當天有人**的代號。
  - ⚠️ 沒有這個人：有勤務、但當天沒有人是這個代號，下一行列出代號。原因有三種：數字代號在姓名對照表上那格是空白的（「姓名欄空白」，例如 10/14 的 76）；中文、英文固定代號照**目前的設定**（`固定代號`，用那天適用的設定），沒有設定給任何人、也沒有配到姓名，就是沒有這個人，照片上那格是不是空白都一樣（「固定代號沒有設定」，例如 10/14 的未、申、E）；在 LINE 上設定的日期比這張班表晚的固定代號，那天還是照姓名對照表讀（和數字代號一樣：那格空白才是「姓名欄空白」，否則算沒讀出來）；班表的姓名對照表根本沒印這個代號（「班表上沒有這個代號」，例如辰、巳、36–53）。這種代號有勤務，多半是勤務格的代號讀錯了；兼服的「#26」這種格子例外。
  - ❓ 信心較低的格數。
  - ⬜ 當天空白的代號：照片上姓名欄是空白的**數字**代號，有沒有勤務都列（10/14 是「9 個」，下一行「26、54、55、56、76、77、78、83、84」），讓管理員核對空白格有沒有讀對；姓名對照表讀到了卻一格空白都沒有時寫「沒有」，那多半是讀錯了。固定代號照設定，不列在這裡。

  方格下面是三塊細節（沒有的就不出現）：「⚠️ 沒有這個人，卻讀到勤務」每個代號寫原因，下一行是勤務在哪幾個小時（例如「76（姓名欄空白）」「14–16 國際線」，最多 6 個代號、每個 3 段，其餘寫「等 N 格」「…還有 N 個代號」），並提示多半是勤務格的代號讀錯了、請對照原圖，固定代號其實有人時傳 `代號 未 姓名` 設定；「❓ 信心較低的格子」依時間一格一行，寫時段、勤務、代號和姓名、信心（例如「08–09 國際線　72 蘇志明 58%」，最多 10 格）；「🔍 姓名沒讀出來」每個代號寫照片上最常讀到的字（例如「32：照片上讀到「羅志明」」，讀不出字就寫「照片上的字讀不出來」，最多 12 個），並提示名冊上沒有這個姓名時傳 `新增人員 姓名` 加進名冊、之後就會配對，或請本人傳 `我是 32 10/14`（帶著這張班表的日期，免得對到別天）。設定 `LINE_V2_PUBLIC_BASE_URL` 時，卡片下面接著送**勤務人員原圖**（和 `勤務人員` 附的姓名代碼對照表裁切同一張），同一次推播；原圖裁切失敗時只送卡片（記錄寫「勤務人員對照圖失敗」），卡片最下方有「查看整張班表」。最壞的情況（118 個代號、每一塊都滿）卡片約 16 KB，LINE 的上限是 30 KB。日期讀錯時點卡片上的「📅 日期不對？點這裡改這張的日期」，用 LINE 的日期選擇器改**這一張**（打字的 `日期 月/日` 改的是最後傳的那張，可能已經是別張）；改日期不會再次通知。之後才發現的話，在班表月曆點那天，單日班表卡片上也有同樣的「📅 改這張的日期」（見「日期不對時：看得到、改得到」）。
- ⚠️ **群組班表辨識失敗**：失敗原因（意外的錯誤會附上錯誤類型），以及有沒有私訊告知上傳者（預設不推播時寫「已放進他的收件匣」）。原有班表不變。
- 🚫 **不像班表，已略過**：找不到班表的表格框線，或讀不到日期、姓名、代號的照片。如果其實是班表，多半是四個角沒拍進去或太模糊，請重拍後再傳；一般照片忽略即可。
- 推播開啟時，日期讀不到的班表不另外回報，管理員收到的是下面那張詢問日期的卡片；預設不推播時照常回報（「📅 班表日期」寫「日期未辨識」），用卡片上的「📅 日期不對？」補上日期。私訊給機器人的照片不回報。
- 管理員自己在群組傳照片時，只收到回報卡片，不會再收到給上傳者的提醒。

#### 管理員：群組人流資料的讀取結果

群組裡被認出是航班人數的訊息（有 `【國內 – 離站】` 這類段落和至少兩行 `6-7時：2架74人`），不論有沒有記下，都會**給每位管理員一張卡片**，和群組照片的辨識回報同一款，群組裡照樣不回覆。
預設不推播：卡片放進管理員的收件匣，跟著下一次回覆送出，不用額度。推播開啟（`LINE_V2_PUSH=1`）時馬上推播，這張卡片是 push，**會用掉每月的訊息額度**：每則訊息、每位管理員各 1 則，例如 2 位管理員、群組一個月貼 30 則航班人數就是 60 則；和班表照片的辨識回報加起來算（免費的輕用量方案每月只有 200 則）。

- ✅ **群組人流資料讀取成功**（綠色）：誰貼的（登記的姓名，沒登記時是他在群組的 LINE 名稱，和辨識回報相同）、幾點貼的（台灣時間，例如「華華｜10/13 16:14 傳到群組」），下面是資料日期和讀到的各線人數（✈️ 國際出境、🏠 國內離站…，一線一行）。同一天已經有別則時多一行版本：「🔄 取代了同一天較早貼的那則」；內容一模一樣時「🔁 和同一天原本的資料相同」；同一天已經有更晚貼的一則時「🗂️ 同一天已有更晚貼的一則，預測仍用那則」（這則只存檔）。卡片最下方「📊 看 10/6（二）的人流預測」直接打開那天的人流預測卡片。
- ⚠️ **群組人流資料沒有記下**（橘色）：原因、資料日期（有的話）、讀到的人數，和怎麼做。「只有到站／入境」：人流預測只看離站／出境，含「離站」或「出境」段落的那則貼到群組就會記下，只有到站的訊息不用理會；「訊息裡沒有日期」：連同日期那一行重貼到群組。
- 每則航班人數訊息，每位管理員只推播一次、一張卡片；同一則訊息被 LINE 重送不會再推播。私訊貼給機器人的航班人數訊息本來就會直接回覆，不推播、也不另外留讀取結果；沒有設定管理員時都不留。
- 讀取結果同時存在資料庫（`flow_notices` 表）。只要有一位管理員收到卡片就算送達（預設不推播時，放進收件匣就算送達，下面的備用文字不會再重複一次）；**所有管理員都沒收到時**（userId 填錯、沒加好友、封鎖，或本月額度用完），才改用以前的免費方式：等管理員下一次收到機器人的回覆時（打指令、按選單、查班表、私訊照片的辨識結果都算），放在那次回覆的最前面一起送出（Reply 免費），和意見回饋當天第二則以後的送法一樣。這個備用方式送的是文字：

```text
📊 人流資料讀取結果（2 則）

✅ 10/6（二）的航班人數已記下
華華・10/5 21:05 貼到群組
國際出境 3,924 人、國內離站 3,412 人
🔄 取代了同一天較早貼的那則

⚠️ 沒有記下：訊息裡沒有日期
林小明・10/5 21:12 貼到群組
國際出境 3,924 人、國內離站 3,412 人
👉 請連同日期那一行（例如 2026年10月06日）重貼到群組。
```

- 備用方式把還沒送到的全部合成一則，最新的在最下面；超過 8 則時只列最近 8 則，較早的寫成一行「另有 N 則較早的：✅ 幾則已記下、⚠️ 幾則沒有記下」。只給一位管理員看一次：哪位管理員先收到回覆，就出現在他的回覆裡，之後不再出現；其他同仁看不到。回覆沒送出去（例如回覆逾時，改用推播送出）時不附帶、不算看過，下次再送。
- LINE 一次回覆最多 5 則，原本的回覆一則都不會少：還有空間時意見回饋和人流資料各佔一則，放在最前面；只剩一則的空間時兩者合成一則（意見回饋放不下的部分留到下次）；回覆本身已經 5 則時兩者都等下一次。
- 人流預測卡片最下方的「資料：群組 10/6 08:12 貼的航班人數」寫著預測用的是哪一則、幾點貼的。

#### 管理員：日期讀不到時先確認再通知

這一節是推播開啟（`LINE_V2_PUSH=1`）時的做法；預設不推播時日期讀不到的班表直接發布，管理員在收件匣的辨識回報上補日期（見「不推播」）。

在 `.env` 設定 `LINE_V2_ADMIN_USER_IDS`（管理員的 LINE userId，多位用逗號分隔）、而且推播開啟時：

- 群組班表的表頭日期讀不到時，**先不通知任何人**，也不私訊上傳者；只私訊管理員一張卡片（設定了 `LINE_V2_PUBLIC_BASE_URL` 時先附原始照片；這則是 push，每張、每位管理員計 1 則訊息額度）。卡片上有上傳當天起三天的日期按鈕、「📅 其他日期」（日期選擇器，舊班表後來重貼時選更早的那天）和「略過這張」（不通知、日期維持未辨識）。管理員按下日期（或在「其他日期」選好日期）後，才照平常的方式通知已開通知的人：同一天已有較早的照片就是「🔄 班表更新」並比對勤務；同一天已有更晚傳送的照片則只存檔、不通知。沒有人開通知時，卡片只談補上日期，按下後不會發任何通知。
- 只有卡片上的按鈕（和日期選擇器）會發出通知。管理員輸入 `日期 月/日` 時，如果有班表在等日期，機器人會回一張確認卡片，按下去才通知；打字沒有指明是哪一張照片，所以不會直接通知全隊。有班表在等日期時，`日期` 指的一律是最新的那張等待中的班表；要更正別張，先把等待中的處理掉（按日期或「略過這張」）。
- 群組班表的日期只有管理員能更正：在那天的單日班表卡片點「📅 改這張的日期」改那一張；或打字，沒有班表在等日期時，管理員的 `日期 月/日` 更正**最後傳送**的那張（群組的或自己私訊的），回覆會說明是哪一張，不會再次通知。其他人輸入 `日期` 只能更正自己私訊傳的照片。
- 管理員確認之前，這張班表沒有日期，`我的班表` 和日期都查不到它，也沒有人收到通知。建議至少設兩位管理員；先按的人決定，另一位再按只會被告知已處理。
- 所有管理員都收不到私訊時（userId 填錯、沒加好友、封鎖，或本月訊息額度用完），不會把班表扣著：改為直接通知（顯示「日期未辨識」），並在記錄印出警告。
- 沒有設定這個變數時，行為和以前相同：直接通知、私訊上傳者（附「📅 選這張的日期」，只能改自己傳的那一張）、任何人可用 `日期` 更正。
- 自動通知關閉時（預設，見「自動通知」）沒有人會被通知：卡片只談補上日期，確認後大家就能用日期查到這張；私訊管理員的這一則仍會送出。
- 管理員同時是意見回饋與群組人流資料讀取結果的收件人（見「意見回饋」、「管理員：群組人流資料的讀取結果」）。

userId 是 `U` 開頭加 32 個十六進位字元，**不是**加好友用的 LINE ID，而且每個 provider 各不相同。取得方式：私訊機器人 `我的ID`；或 LINE Developers Console → 這個 channel → Basic settings → Your user ID（Business ID 沒有連結 LINE 帳號時不會顯示）。設定後重啟，記錄會印出「管理員：N 位」，管理員私訊 `我的設定` 會看到「管理員：是」；格式不對的項目會在記錄中警告並略過。

本機模擬器用 `python -m all_staff.cli line-sim --admin U_ming` 指定管理員。`line-check` 會把等待中的班表標成「等管理員確認，尚未通知」。

#### 勤務欄範圍、浮動視窗與舊班表重讀

- **勤務欄**：主表的勤務格是 `c02–c36`（每張 19 列 × 35 欄＝665 格）。除了原有的 `c02–c32`，最右邊四欄 A1A3站（c33）、內機（c34）、內部管理（c35）、全區帶勤（c36）也會讀，個人班表、`查 代號`、`查看工作`、`勤務人員` 都看得到；內機欄常是上下兩行（例如 80／81），會分開讀。`查看時段` 的國際（c02–c16）、國內（c17–c30）範圍不變。
- **浮動視窗與備註**：班表截圖有時會蓋著浮動視窗（含尖角的對話框）或合併儲存格的備註文字（例如「72.73 防爆訓練」「81.28.K.F.L 專案」），那些是註解、不是勤務，不能讀成代號。辨識時逐條檢查格線在照片上看不看得見：視窗底下的內部格線被蓋掉、外框還在，這個方塊（至少 4 格、跨 2 欄以上、最多 40 格）整塊不採用；視窗的尖角壓到的格子只丟掉信心低於 0.8 的讀值。被丟掉的讀值保留在該格的 `ignored` 欄位（網頁檢視可查），整張總覽圖（網頁的「原圖」）用**紅框**標出視窗、**橘框**標出尖角格，核對時一眼看得到；備註文字本身不會出現在查詢結果。只蓋住 1–3 格的小標籤、單一欄的細長條，不算視窗，裡面若真是代號（如 子丙、乙寅）照常讀入。照片太糊、格線大半看不清楚（內部格線看不到的比例超過 5%，或判定的視窗合計超過 80 格）時，視窗過濾自動關閉，保留全部讀值，寧可多一個誤讀，也不因為偵測失誤丟掉真實代號。
- **舊班表重讀**：格線規則以 `GRID_VERSION` 標記（2＝`c02–c36`＋過濾視窗；舊版沒有標記）。資料庫裡舊版讀的班表（沒有最右四欄、視窗文字被當成勤務）會用保存的原始照片重讀：機器人啟動時在背景從最新的一張開始，預設最多 20 張（環境變數 `LINE_V2_REGRID_LIMIT`，`0` 關閉），每張約 20–30 秒，期間新照片的辨識排在後面；重讀完成前舊結果照常可查。重讀失敗不會動到原結果，也不會每次啟動都重試。想一次全部重讀，或只讀特定幾張：

```bash
python -m all_staff.cli reanalyze                            # 全部舊版班表，最新的先
python -m all_staff.cli reanalyze --limit 5                  # 只讀最新的 5 張
python -m all_staff.cli reanalyze --run 20261004-… --force   # 指定一張，已是最新版也重讀
# Docker：docker compose run --rm work-schedule-line-v2 conda run --no-capture-output --name work python -m all_staff.cli reanalyze
```

手動重讀請在機器人停止時執行（兩個程序同時改同一張班表沒有互相鎖定）。重讀後的個人標示圖與時段圖檔名會多一個 `-g2`，避免 LINE 繼續顯示以前快取的舊圖。

#### 姓名對照表的辨識

`all_staff/name_table.py` 以主表格的定位把整頁拉正（放大 2.5 倍取樣），用形態學找出對照表每一欄自己的橫線
（離一條明顯橫線不到 0.7 列的淡筆畫不算橫線，免得一格被切成兩半、下面的代號全部差一列），
再讀每一欄「代號」格裡印好的代號（1–14、15–28、29–35＋甲…庚、辛…酉＋54–56、57–70、71–84、A–N）。
七欄是同一張表，第一列在同一個高度：程式先用相鄰欄的橫線算出拍歪造成的逐欄高低差（只看線的位置，不靠 OCR），
再把七欄讀對的印刷代號加總，找出整張表讀對最多代號的第一列位置——單獨一欄只要碰巧讀對 1、2、4 三格，就可能整欄錯位十列，所以不單看一欄。
整張表讀對的代號少於 5 個，或另一個位置幾乎一樣好時，整張表不採用姓名：寧可沒有姓名，也不會把姓名放到別人的代號上
（舊版本是用平均列距推算，照片下緣彎曲時會整欄偏移幾列）。各欄的列再沿著共用的橫線一列一列接下去，某條橫線沒偵測到只會少那一列，不會把下面的列整個往上推。
表格拍歪時，欄與欄之間的直線也跟著傾斜：姓名格沿著實際找到的斜直線切（至少三欄、寬度一致才採用，否則維持垂直切法），避免姓名被切進隔壁欄；某一欄中間有幾條橫線太淡讀不到時，依列距補上（一次最多補 9 格）。
姓名格用 `assets/tessdata/chi_tra.traineddata`（Tesseract fast 模型）讀四種前處理版本，再對照 `configs/staff_names.txt`（安檢隊名單，一行一位）
＋同仁自己登記的姓名：必須明顯最像某個姓名才採用，版本之間不一致或同名出現兩次就放棄
（2026/9 的 23 張照片：約 1520 個姓名、9/19 抽查沒有配錯）。
2026/10/3 加入斜線切格與補列後，21 張照片多讀出 37 個姓名、少 1 個（9/12 的一格 OCR 不穩），沒有任何一個配錯（多出的逐一目視核對）；仍讀不出的多半是 OCR 雜訊，可用 `我是 代號` 補登。
2026/10/3 晚間加入 10 月照片（10/1–10/4、10/2 更新版，以及 9/27 更新版、9/29、9/30）後，29 張照片的 98 個姓名格全部定位。10/2 更新版原本有兩欄（15、辛）被略過、只讀到 50 個姓名，現在讀到 77 個，且與同一天第一張照片一致；9/26 少的一格也補上。
另外對 29 張照片各做模糊、縮小、雜訊、褪色共 203 組劣化測試：舊版有 19 格姓名放到別人的代號上（10/2 更新版縮小後），新版 0 格——整張表不夠清楚時就不採用姓名。
`NAMES_VERSION` 升為 5，資料庫裡的舊班表第一次被查詢時會自動重讀一次姓名。
10 月班表上癸、丑、寅、卯四格已是空白（彭彥銘、陸以諾、吳承恩、徐正洹確認離隊），不會再有姓名配到這四個代號。
定位到的姓名格裡完全沒有筆跡時，會記成「空白格」（存在 `result.json` 的 `names_blank`），和「有字但沒讀出來」分開：有勤務的數字代號那格是空白的，就是當天沒有這個人（「姓名欄空白」）；固定代號不看照片上那格是不是空白，照目前的設定，沒有設定給人、也沒配到姓名的就是當天沒有這個人（「固定代號沒有設定」）；姓名對照表沒印的代號（辰、巳、36–53）也一樣（「班表上沒有這個代號」）。管理員回報卡片（「⚠️ 沒有這個人」和「⬜ 當天空白的代號」）、`勤務人員`（那一格寫「空白」「沒設定」或「表上沒有」）、`查看時段`、`查看工作`（「⬜ 76（姓名欄空白）、未（固定代號沒有設定）：當天沒有這個人，請對照原圖」，最多列 12 個代號）、伺服器記錄和 `line-check` 都和「姓名未辨識」分開列。判斷刻意保守：姓名是淺灰色印的，照片稍微亮一點、糊一點就會比固定門檻（灰階 150）還淡，所以是看格子中間「比這格自己的底色暗 20 以上」的筆跡佔多少（`BLANK_STROKES` 0.5%，同時暗於 150 的也要少於 1%）。10/13 那張照片調亮、降對比、淡化、縮小、模糊後試過，有姓名的格子都不會被當成空白；拿不準時寧可算沒對到，也不會把真的沒讀到的姓名說成空白。整欄代號核對不了而略過的格子不算空白，只是不知道。這不需要升級 `NAMES_VERSION`：之前存的班表沒有這一項，數字代號照舊算沒讀出來，重讀姓名時才補上；固定代號和沒印在表上的代號照上面的規則。

#### 人員管理（幹部）

人員增減不用再改程式或設定檔：**幹部**私訊機器人 `人員管理`，就能在 LINE 修改名冊、固定代號和幹部名單，改完馬上生效（已上傳的班表也會照新的名冊重新配對姓名，不用重傳）。只有數字代號每天換；中文代號（甲乙丙丁戊己庚辛壬癸、子丑寅卯辰巳午未申酉）都是**役男**的固定代號，英文代號 A–N 也是固定的。

**卡片**（都是 Flex，不用 LINE 的按鈕元件，所以文字不會被截成「人員…」）：

- `人員管理`：上方漸層區顯示名冊、代號（固定代號已設定幾個／34）、已登記、幹部四個數字；下面七個可以點的方塊：人員名冊、固定代號、新增人員、刪除人員、幹部名單、新增幹部、綁定清單，一排兩個。**管理員**的卡片多兩個方塊，在綁定清單前面自成一排（管理員選單上已經沒有這兩顆按鈕）：「📮 姓名申請」（送出 `姓名申請`；有申請在等時寫「N 筆等你確認」、方塊變成橘色，沒有時寫「審核改名與登記」）和「💬 意見列表」（送出 `意見列表`；有還沒有管理員看過的意見時寫「N 則新的意見」，這些意見也會跟著這次回覆放在卡片前面，沒有時寫「大家的意見回饋」）。幹部的卡片沒有這兩個（這兩個指令只有管理員能用）；標題下寫「幹部專用」，管理員看到的是「管理員專用」。「新增／刪除人員」「新增幹部」點下去會直接打開鍵盤並帶入指令（LINE 12.6 以上），機器人同時回一則說明和快速按鈕，舊版 LINE 照著按也行。最下面「📖 人員管理指令」列出人員管理的全部文字指令（傳的是 `人員管理指令`；一般同仁打 `所有指令` 照舊看到進階說明）。上方的「已登記」只算名冊上的人，自己登記但不在名冊的人另外在提示裡列出。
- `人員名冊`：「沒有固定代號」的同仁（數字代號每天換；剛清空代號的役男也在這裡）排成四欄表格、隔行淺灰；已在機器人登記的人是綠色粗體加 ✓。下面是 20 個役男代號和 14 個英文代號（沒人的留空，已登記的一樣有 ✓），再下面是「自己登記、不在名冊」的人，按一下「這 N 位全部加入名冊」就加進去。名冊很長、一張卡片放不下（LINE 每張上限 30KB）時，第一頁放固定代號和按鈕並提示往左滑，姓名分在後面幾頁；整組還是超過 LINE 一則 50KB 時，固定代號改到「固定代號」卡片看，再放不下的人會註明沒有列出。
- `固定代號`（也可以打 `役男代號`、`英文代號`）：「🎖️ 役男（中文代號）」甲到酉 20 格、「🔤 英文代號」A 到 N 14 格全部列出，有人的格子是淺色底加姓名，沒人的留空。**點格子**就會打開鍵盤並帶入「役男 丁 」或「代號 A 」，打姓名送出就完成；設定後回傳更新過的格子，剛改的那格會加框。點有人的格子，回覆下方有「清空」。
- **先打姓名也可以**：`役男 王小明` 會回傳同一張格子，這時**點空白的格子一下就設定好**（不用再打一次姓名），下方快速按鈕也列出幾個空的代號；他已經有代號的話會先說是哪一個。`新增人員` 加完人，回覆下方有「📌 給王小明代號」直接進到這一步。點格子時如果那個代號剛好被別人設定走了，機器人會先問要不要換，不會直接蓋掉。
- **名冊裡還沒有的人，先確認再寫入**：`役男 丁 王小明` 裡的王小明不在名冊、也沒登記時，機器人會問「要把丁給他，並把他加進名冊嗎？」，按「✅ 新增並給丁」才會寫入；只打 `役男 你好` 這類名冊裡沒有的字，只會提供「➕ 新增…」，不會出現一按就設定的格子。代號後面接問句（`代號A是誰`、`役男 丁 是誰`）會告訴你這個代號現在是誰。
- 「固定代號」與「人員名冊」的格子裡，已在機器人登記的人是綠底加 ✓。
- `幹部名單`：每位幹部一列，職稱做成標籤；下面有新增幹部／移除幹部方塊。
- `綁定清單`（也可以打 `綁定名單`、`登記清單`、`登記名單`）：每個已登記的 LINE 帳號一列「姓名｜LINE 名稱｜職稱（管理員、幹部）」，依名冊順序，用來確認每個姓名後面是誰的 LINE、有誰看得到班表。最上面先列要處理的：「⚠️ 同一個姓名有好幾個帳號」（一個姓名只能一個帳號；規則上線前留下的重複，點那一格就會問要解除哪一個）；最下面是「🚫 不在名冊」（姓名不在名冊上，看不到班表，幹部和管理員除外）。LINE 名稱在登記時記下，之後對方每次傳訊息時最多每天向 LINE 更新一次；LINE 沒給名稱時顯示 userId 的最後四碼。名單很長時分頁左右滑，放不下的會註明有幾個沒列出。還沒登記的同仁看 `人員名冊`（沒有 ✓ 的）。

| 指令 | 作用 |
| --- | --- |
| `新增人員 王小明 陳大華` | 加入名冊，一次可加好幾位（空白、頓號、逗號隔開都可以） |
| `刪除人員 王小明` | 從名冊移除；對方有固定代號的話一併清空。對方自己用 `設定` 登記的姓名不受影響（對方傳 `解除`、或幹部傳 `解除登記 王小明` 才會取消），但不在名冊上就看不到任何資訊（見「名冊守門員」） |
| `役男 丁 簡志明` | 把代號「丁」給簡志明；原本有人用 `丁` 時改成新的人。**役男換人，原本那位會一併移出名冊**（不會留在「沒有固定代號」那一區變成每天換數字代號的人；他登記的 LINE 帳號從此看不到班表，幹部和管理員除外），換人前的確認訊息和換人後的回覆都會寫明，並附「➕ 加回…」一鍵復原。換人的日期會另外記下（`fixed_staff_codes.former.json`；用「清空」再「移出」或 `刪除人員` 讓役男離開時也一樣會記），所以換人日**之前**的班表仍然認得原本那位、照樣顯示他，接手的人也不會把之前的班表和時數算到自己頭上；從離開那天起的班表則完全不會再配到他，即使他的 LINE 帳號還登記著那個姓名（加回名冊就恢復）；簡志明原本的代號會清空，不在名冊時自動加入。也可以打 `役男 簡志明 丁`、`役男丁簡志明`；舊的 `固定代號 丁 簡志明` 一樣可以用 |
| `代號 A 簡志明` | 英文代號一樣這樣設定（`代號 a 簡志明`、`代號A簡志明`、`英文代號 A 簡志明` 也可以）；只接受 A 到 N。英文代號換人時，原本的人仍留在名冊上。`代號 72` 這類數字代號不是固定代號，機器人照舊不處理 |
| `役男 丁 取消`／`代號 A 取消` | 清空這個代號（人仍留在名冊）；`清空`、`刪除` 也可以。清空役男代號時，回覆下方有「➖ 移出…」一鍵把退伍的人從名冊拿掉 |
| `綁定清單` | 每個已登記的 LINE 帳號（LINE 名稱）用的是哪個姓名；幹部和管理員都可以看 |
| `解除登記 王小明` | 解除登記這個姓名的 LINE 帳號（換了帳號、被別人登記走、離隊）：對方變成沒有登記姓名、看不到班表，要重新 `設定`；不會推播通知對方。同一個姓名有好幾個帳號時會先列出編號（依登記先後，每列有 LINE 名稱、登記日期和 userId 末四碼），再傳 `解除登記 王小明 2` 或 `解除登記 王小明 全部`；每解除一個，回覆會把剩下的帳號重新編號列出，下一個請照新的編號。解除後這個姓名就空出來，**先傳 `設定 王小明` 的帳號就會登記到**（已經登記過別的姓名的帳號仍要管理員同意），所以請讓本人馬上登記；姓名不在名冊上時要先 `新增人員`。被解除的是幹部或管理員時，對方仍然看得到班表（身分跟著 LINE 帳號）。`解除綁定 王小明`、`取消登記 王小明` 也可以；後面不加姓名的 `解除`／`取消登記` 仍然是取消自己的登記 |
| `役男 丁`／`代號 A` | 看這個代號現在是誰，以及怎麼換人或清空 |
| `新增幹部 王小明 副隊長` | 用對方**登記的姓名**加入幹部（對方要先私訊 `設定 王小明`），職稱可省略；也可以用 `新增幹部 U…`（對方私訊 `我的ID` 查得到） |
| `移除幹部 學姊` | 用姓名、職稱或 userId 移除；只剩最後一位幹部、又沒有設定管理員時會拒絕，避免沒人能管理 |
| `姓名申請` | 管理員專用：列出等待確認的改名／登記申請，直接點「✅ 同意」或「❌ 不同意」；幹部傳了只看到自己的申請進度（見「姓名鎖定與改名申請」）。管理員的 `人員管理` 卡片上有這個方塊 |
| `意見列表` | 管理員專用：最近 10 則意見回饋（見「意見回饋」）；管理員的 `人員管理` 卡片上有這個方塊 |
| `人員管理指令` | 列出上面這些指令（卡片上的「📖 人員管理指令」） |

- **從設定那天起套用**：在 LINE 設定或換人的固定代號，會記下設定的日期（`fixed_staff_codes.since.json`，和代號檔放在一起），從那天的班表開始套用；更早的班表照當天的姓名對照表配對。這樣英文代號就算以前每天換、或者某個代號換給新的人，也不會改寫以前的班表和本月統計。`configs/` 原本就有的中文代號沒有日期，照舊套用到所有班表。
- 姓氏剛好是天干地支的人（例如王志明、施志明、新來的丁小明）：`役男丁小明` 這種沒有空白的寫法，只有在後面是名冊上的姓名、或是完整三個字的姓名（`役男丁王大同`）時才拆成代號＋姓名，而且後面那個姓名不在名冊時一樣要先按確認；其他情況一律當成一個人的姓名，不會寫入「丁＝小明」。代號和姓名之間用空白、頓號或逗號隔開都可以（`役男 丁、王小明`）。
- 一般同仁打 `役男`、`英文代號`、`代號表` 這類字、查某個代號（`役男 丁`、`代號A是誰`），或沒有要設定什麼的句子，照舊得到一般的回覆。管理用的畫面（`人員管理`、`人員名冊`、`固定代號`／`役男代號`、`幹部名單`、`人員管理指令`）和真的要改名冊或代號的指令，才會被告知「只有幹部可以使用」。
- 幹部和管理員的 1:1 選單最下面多一排「管理」（人員管理、人員名冊，再加幹部的固定代號或管理員的辨識回報），`新增幹部`／`移除幹部` 後會自己換（見「1:1 聊天室下方的選單」）。
- 只有幹部和管理員（`LINE_V2_ADMIN_USER_IDS`）能用，其他已放行的同仁輸入會被告知「只有幹部可以使用」，什麼也不會改；還沒放行的人（沒登記名冊上的姓名）只會收到名冊守門員的卡片。群組裡一樣不回應。
- 第一批幹部寫在 `configs/officers.json`（學姊、隊長），**只在資料庫第一次啟動時匯入**；之後一律用 `新增幹部`／`移除幹部`，改這個檔不會再生效，被移除的幹部重啟後也不會回來。幹部存在 `data/line_v2/bot.sqlite3` 的 `officers` 表。
- 正式環境的名冊在 `data/line_v2/staff_names.txt` 和 `data/line_v2/fixed_staff_codes.json`：第一次啟動時從 `configs/` 複製過去，之後機器人、姓名對照表與休假表辨識、`line-check`、`reanalyze` 都讀這兩個檔。`data/` 有掛載，重建映像不會蓋掉幹部的修改；`configs/` 裡的兩個檔只是新安裝的起始名單。LINE 新增的姓名後面會附註日期和是誰加的，例如 `王小明  # 2026-10-08 隊長 林大明 新增`。
- 每次修改都會印在記錄裡（誰、改了什麼）。
- 本機模擬器在 `--folder` 裡用自己的複本，不會改到 `configs/`；用 `--admin U_ming` 讓模擬使用者可以管理人員。模擬器會畫出卡片的標題區（漸層）、可以點的方塊和格子：點「新增人員」或代號格子會把指令帶進輸入框，同時照 LINE 的做法送出 postback。

姓名格保留完整字形，只去掉一個像素的格線邊界。四次整批 OCR 後，尚未配對且有文字的格子會用單行模式再讀灰階與二值化版本；仍未配對的格子再試窄邊界，兼顧字填滿格子及字較小的照片。空白格不重讀，單格逾時也會保留其他已成功讀取的姓名。仍使用原本的相似度、歧義與重複姓名檢查，沒有降低門檻。姓名讀取版本更新為 3，舊結果在首次查詢時會從保存的照片重讀一次，補上已上傳班表的漏名，不需重新上傳。

舊版讀的姓名（或還沒讀過的舊班表）在第一次被查詢時會自動從原始照片重讀一次。也可以一次全部檢查／修復：

```bash
python -m all_staff.cli line-check                  # 每張班表：來源、使用中的日期／照片上的日期、姓名數、有勤務沒對到的代號、有勤務但當天沒有這個人的代號（附原因）、無法核對的欄、「我是」
python -m all_staff.cli line-check --reread         # 全部從照片重讀姓名對照表
python -m all_staff.cli line-check --restore-dates  # 把被「日期」改過的班表改回照片上辨識到的日期
# Docker：docker compose run --rm work-schedule-line-v2 conda run --no-capture-output --name work python -m all_staff.cli line-check
```

### 1:1 聊天室下方的選單（圖文選單）

```bash
python -m all_staff.cli line-menu
# 或在 Docker 裡：docker compose run --rm work-schedule-line-v2 conda run --no-capture-output --name work python -m all_staff.cli line-menu
```

會上傳三張選單（都是 2500×1686），一般選單設為所有好友的預設選單，幹部和管理員各自換上自己的那張：

| 選單 | 誰會看到 | 圖片 | 最下面多的「管理」排 |
| --- | --- | --- | --- |
| 一般選單（`roster-bot-v2`，預設） | 所有好友 | `assets/line_rich_menu.png` | 沒有，就是下面說的四排 |
| 幹部選單（`roster-bot-v2-officer`，聊天室下方寫「幹部選單」） | 幹部（`幹部名單` 上的人） | `assets/line_rich_menu_officer.png` | 人員管理／人員名冊／固定代號 |
| 管理員選單（`roster-bot-v2-admin`，寫「管理員選單」） | 管理員（`LINE_V2_ADMIN_USER_IDS`），同時是幹部的也用這張 | `assets/line_rich_menu_admin.png` | 人員管理／人員名冊／辨識回報 |

一般選單共四排，左側用圖示、分類名稱與配色分組：班表（我的班表）、查詢（查看時段／查看工作／查詢人員）、人員（勤務人員／休假人員／人流預測）、更多（本月統計／我的設定／意見回饋）。左側分類標籤只作指示，右側十個功能可點擊（LINE 一張選單最多 20 個）；「班表」整排只有一顆「我的班表」（每天最常用：現在、下個小時、明天都在同一張卡片），畫成一顆置中的寬按鈕（時鐘圖示＋「現在、下個小時、明天」），整排都可以點；查詢、人員、更多三排每排三顆、字級一樣（`ROW_COUNTS = (1, 3, 3, 3)`、`ROW_FONTS`），文字放不進格子時 `--dry-run` 會直接報錯。「更多」那排以前還有一顆「用法說明」（一排四顆、字級略小），現在拿掉了：說明照樣用打的，傳 `說明`（或 `用法說明`）就會出現，說明卡片最後也寫著「想再看這四張說明卡，隨時傳「說明」。」
幹部選單和管理員選單是同樣的四排，再加第五排「管理」（酒紅色、盾牌圖示），讓幹部不用打字就能進 `人員管理`。五排擠在同樣的高度裡（LINE 規定圖片的寬至少是高的 1.45 倍，不能再加高），所以每一排的字、圖示和間距都跟著縮小一點；文字放不進格子時一樣會報錯。兩張的「管理」排都是三顆、和上面幾排對齊，前兩顆一樣：人員管理（名冊、代號、幹部）、人員名冊（誰在名冊上）；第三顆幹部是 `固定代號`，管理員是「辨識回報」（班表與人流），送出 `辨識回報`，打開自己的收件匣（見「不推播」）。管理員的 `姓名申請`、`意見列表` 不在選單上，是 `人員管理` 卡片上的兩個方塊（見「人員管理（幹部）」）；這兩個指令只有管理員能用，所以幹部的卡片沒有。

**這一版（拿掉「用法說明」、管理員的「管理」排改成人員管理／人員名冊／辨識回報）部署之後，要再上傳一次選單**：先部署並重啟伺服器，再執行 `python -m all_staff.cli line-menu`（Docker：`docker compose run --rm work-schedule-line-v2 conda run --no-capture-output --name work python -m all_staff.cli line-menu`）。選單圖片和按鈕存在 LINE 那邊，部署程式不會改變它；還沒重新上傳之前，大家看到的還是舊選單，舊的「用法說明」「姓名申請」「意見列表」按鈕照樣可以按（這些指令都還在），從更早、還沒有「辨識回報」按鈕的選單更新的管理員打 `收件匣` 一樣看得到辨識回報。

**誰用哪一張，機器人會自己換**：伺服器啟動時（在背景，不會拖慢啟動）、`新增幹部`／`移除幹部` 之後、幹部或管理員重新加好友時，機器人會幫幹部和管理員連結自己的選單；已經不是幹部或管理員的人改回一般選單。換過的人記在 `data/line_v2/bot.sqlite3` 的 `menu_links` 表，沒有變的不會重複呼叫 LINE。

- `新增幹部` 的回覆會多一行「他重新打開聊天室後，選單最下面會多一排「管理」。」，`移除幹部` 會說「選單的「管理」那排會收起來」；只有真的換成功才這樣說。LINE 沒回應或出錯時，回覆照樣送出、只是不提選單（最多等 3 秒），記錄會印出失敗，下次伺服器啟動時再換一次。
- `我的設定` 會多一行「選單：幹部版（最下面一排「管理」）」或「選單：管理員版（最下面一排「管理」）」；只有機器人換上的選單還符合他現在的身分、而且還是 LINE 上現在那一張時才顯示。
- 管理員名單在 `.env`，所以加減管理員要重啟伺服器才會換選單（被拿掉的管理員在重啟時改回一般選單；同時是幹部的改用幹部選單）。
- 同樣要重新進入聊天室（有時要重開 LINE）才會看到換好的選單。

**部署這一版之後，要再執行一次 `line-menu`**（先部署並重啟伺服器，再執行上面的指令）：幹部選單和管理員選單要上傳到 LINE 才存在。上傳時會先建好三張新選單、設好預設、把幹部和管理員換到新的選單，最後才刪掉舊的（刪掉選單時 LINE 會一併取消連到它的人），結束時印出「已換上：管理員選單 N 位、幹部選單 N 位」。之後每次重新上傳也一樣會自動換好。有人沒換成時（例如 `.env` 裡的管理員 userId 打錯、對方還沒加機器人好友，或 LINE 暫時出錯）會印出「N 位沒換成」和原因，他們先看到一般選單，伺服器下次啟動時會再換一次。
還沒上傳之前什麼都不會壞：所有人照舊看到一般選單，幹部照樣可以打 `人員管理`（`我的設定` 回覆下方也有這個按鈕），伺服器記錄每次啟動只會印一次「管理員／幹部選單還沒上傳，請執行 python -m all_staff.cli line-menu」。
`line-menu` 要讀 `data/line_v2/bot.sqlite3` 才知道誰是幹部（`--folder` 可以指定別的資料夾），所以請在伺服器上或 Docker 裡、伺服器啟動過之後執行；找不到資料庫時會直接停下、什麼都不上傳（舊選單和大家連結的選單都保留），請改到伺服器上執行或用 `--folder` 指對資料夾。只想重畫圖片用 `--dry-run`，不需要資料庫。

**更新到「我的班表」這一版後，要重新上傳選單一次**（先部署並重啟伺服器，再執行上面的 `python -m all_staff.cli line-menu`）：選單圖片和按鈕存在 LINE 那邊，部署程式不會改變它。還沒重新上傳之前，舊選單的「今天班表」「明天班表」「下個時段」照樣可以按，三個都會打開新的「我的班表」卡片。
「查詢人員」會打開鍵盤並預填 `查 `，「意見回饋」預填 `意見 `；其他按鈕直接送出指令。選單只出現在 1:1 聊天室，不會出現在群組。
登記姓名只需要做一次，所以選單上沒有按鈕：`我的設定`，以及每一則「你還沒登記姓名」的回覆下方都有「設定姓名」按鈕，會打開鍵盤並預填 `設定 `。

新朋友加好友時**不會跳出用法說明**，只收到一張「👋 歡迎加入／第一步：登記你的姓名」卡片，中間一個大大的「✏️ 點這裡，輸入我的姓名」（打開鍵盤並帶入 `設定 `；舊版 LINE 照著回覆下方的按鈕按也行）。登記好之後，回覆的是**今天**的班表；今天的還沒上傳才會是明天的（不會因為隔天班表已經先上傳就跳到明天）。已登記過的人封鎖後再加回來，只會收到「歡迎回來」。
**改選單時先更新伺服器、再上傳選單**：選單是用本機的程式和權杖直接上傳的，伺服器還是舊程式時，新按鈕會得到「我看不懂這句話」。
按鈕在 `all_staff/rich_menu.py` 的 `BUTTONS`（「管理」那排在 `ROLE_BUTTONS`）；修改後執行 `line-menu --redraw` 重畫三張並重新上傳，舊選單會自動刪除。只想看圖可用 `--dry-run`（三張都會重畫，什麼都不上傳）。
使用者通常要重新進入聊天室（有時要重開 LINE）才會看到新選單。

還沒有任何群組上傳班表時，可以私訊傳照片查詢自己上傳的那張；群組有班表後，私訊照片只供此次辨識，不會覆蓋全隊班表，也不會推播。
群組內所有成員傳送的圖片都會嘗試辨識，尚未限制隊長帳號或去除重複照片。

舊資料庫的單位與訂閱資料表會保留但不再使用；既有通知開關與班表不受影響。之前用代號綁定且開了通知的人，下一張群組班表時會收到一次提醒，請他們改用 `設定 姓名`。
正式服務需要更新並重啟 V2（`./linebot_v2_restart.sh`）；程式碼更新本身不會改變已在運行的服務。

本機模擬：`python -m all_staff.cli line-sim`；在模擬群組傳照片即可，快速指令只顯示於私訊。模擬器和正式環境一樣預設不推播（給某人的訊息等他下次傳訊息時才出現），`--push` 可模擬推播。模擬器的選單也照身分換：`--admin U_ming` 的管理員和用 `新增幹部` 加的幹部，私訊下方會多一排「管理」，開發者面板會記下每次換選單（`menu`）。

## LINE Bot（V1）

LINE Bot 收到班表圖片後會先回覆「正在辨識」，完成後以 Push Message 傳回四位員工的結果。這是必要的兩段式流程，因為 LINE 的 Reply Token 時效很短，而班表辨識可能需要數分鐘。

1. 到 [LINE Developers Console](https://developers.line.biz/console/) 建立 Provider 與 **Messaging API channel**，並把該頻道連結到 LINE Official Account。
2. 在頻道的 **Messaging API** 分頁取得 **Channel secret**，並發行 **Channel access token**。兩者都必須保密。
3. 準備可從網際網路存取的 HTTPS 網址；LINE 無法呼叫 Tailscale `100.x.x.x` 或僅限區網的 URL。此服務的 callback 路徑是 `/line/callback`，因此完整網址會是 `https://你的網域/line/callback`。
4. 在 LINE Developers Console 的 **Webhook settings** 填入該 callback URL，按 Verify，然後開啟 **Use webhook**。若只想由程式回覆，請在 LINE Official Account Manager 關閉自動回應與歡迎訊息。
5. 將 `.env.example` 複製為 `.env`，填入：

```text
OPENAI_API_KEY=你的_OpenAI_API_Key
LINE_CHANNEL_ACCESS_TOKEN=Messaging_API_頁面的_Channel_access_token
LINE_CHANNEL_SECRET=Messaging_API_頁面的_Channel_secret
# 公開 HTTPS 服務的根網址；設定後才會一併傳送裁切圖片
LINE_PUBLIC_BASE_URL=https://你的網域
```

裁切圖片由服務的 `/line-crops/` 路徑提供，因此 `LINE_PUBLIC_BASE_URL` 必須是 LINE 可以存取的 HTTPS 網址。若尚未設定公開網址，LINE Bot 仍可回覆文字班表，只是不會傳送裁切圖片。

### Linux 正式部署（Docker + Cloudflare Tunnel）

這個專案只保留一個正式部署版本。請在 Linux 伺服器上執行 Docker Compose；Cloudflare Tunnel 也會在 Compose 中運行，伺服器不需要開放 `8080` 或任何入站連接埠。

1. 在 Cloudflare Zero Trust 的 **Networks → Tunnels** 建立一個給此 Linux 主機專用的 **named tunnel**，選擇 **Docker** connector 並複製 tunnel token。不要沿用目前 Mac 正在連線的 tunnel；同一 hostname 同時接到兩台主機時，請求可能被送到錯的主機。
2. 在這個新 tunnel 新增 Public Hostname，例如 `line.example.com`。若該 hostname 已加在 Mac 的 tunnel，先從舊 route 移除後再移到新 tunnel。Service type 選 **HTTP**，Service URL 填入 `http://work-schedule-line:8080`。這是 Compose 內部的 service 名稱，不能填 `localhost`。
3. 在 Linux 伺服器取得專案後，建立不會提交到 Git 的設定檔：

```bash
cp .env.example .env
chmod 600 .env
```

填入 `.env` 的 `OPENAI_API_KEY`、`LINE_CHANNEL_ACCESS_TOKEN`、`LINE_CHANNEL_SECRET`、`CLOUDFLARE_TUNNEL_TOKEN`，並設定：

```text
LINE_PUBLIC_BASE_URL=https://line.example.com
LINE_BOT_PORT=8080
```

4. 在 LINE Developers Console 的 Webhook settings 設定：

```text
https://line.example.com/line/callback
```

按 **Verify** 成功後開啟 **Use webhook**。LINE Official Account Manager 的自動回應與歡迎訊息應關閉，避免和 Bot 重複回覆。

5. 啟動或更新正式服務：

```bash
chmod +x linebot_restart.sh
./linebot_restart.sh
docker compose logs --follow work-schedule-line
```

查看 Tunnel 是否已連線則使用 `docker compose logs --follow cloudflared`。若兩個服務都顯示 `Up`，而 Cloudflare route 正確，LINE 的 Verify 應可成功。資料庫與裁切圖片會保留在伺服器專案目錄下的 `data/`。Webhook、訊息接收與 Push Message 的設定細節請參考 [LINE 官方建置 Bot 說明](https://developers.line.biz/en/docs/messaging-api/building-bot/)、[Webhook 說明](https://developers.line.biz/en/docs/messaging-api/receiving-messages/) 與 [訊息傳送說明](https://developers.line.biz/en/docs/messaging-api/sending-messages/)。

## 本機模擬 LINE，保留每次問答與辨識過程

```bash
# 依日期順序跑 data 中的 9/10～9/19（支援 9:18.jpg、9_18.jpg、9-18.jpg）
python3 simulate_line.py

# 指定一張；每次執行皆建立新的紀錄，舊紀錄不覆寫
python3 simulate_line.py 'data/9:18.jpg'

# 同時跑三張，縮短批次測試時間
python3 simulate_line.py --from-day 10 --to-day 19 --jobs 3
```

使用 `.env` 的 `OPENAI_API_KEY`、`OPENAI_MODEL` 與正式 LINE template。會呼叫 OpenAI API 並產生費用，但**不會發送 LINE 訊息**，也不需要 LINE token／公開圖片網址。採用正式 `analyze_schedule_image` 與 LINE 文字 formatter；本機圖片引用替代公開 URL。

模擬訊息順序與正式 LINE 相同：收到提示後會先回覆 `perspective-corrected.jpg`，再執行辨識並回覆文字與個人標註圖。即使後續辨識失敗，矯正圖仍會保存在該次對話紀錄中。

輸出位於 `data/line-simulations/<時間-隨機ID>/`。打開 `index.html`，即可點開每一天的對話、文字及圖片。

- `manifest.json`、`template.json`、`code/`、`prompts.json`：這次輸入檔的雜湊、模型、設定、程式與提示詞快照；不保存 `.env` 或 API key。
- 每張照片的 `request.json`、`input.jpg`：原始檔、執行時間、成功／失敗狀態與用量。
- `conversation.html`／`.txt`／`.json`：依 LINE 順序記錄使用者圖片、收到提示、每人的文字／圖片、總價。
- `丁.txt`、`戊.txt` 等及同名 `.jpg`：實際回覆內容；無排班者沒有個人圖片，與 LINE 行為相同。
- `pipeline/grid/`：校正圖、格線 debug、192 格實際模型輸入、contact sheet 與裁切索引。
- `pipeline/api/cells/`、`pipeline/api/text/`：每次 API 回應與耗時，包含 token 用量及辨識輸出。
- `pipeline/recognition.json`／`.md`：第一輪 final grid；`text-before-reconciliation.json`：文字模型原始整理結果；`result.json`：與 final grid 同步後的最終結果。
- 失敗時仍保留原圖、已完成步驟、API 回應、`error.txt` 及模擬 LINE 錯誤回覆，並繼續測下一張。整批有失敗時腳本以 exit code 1 結束。

`completed` 只表示流程執行成功，**不是辨識正確率通過**；請由 debug／contact sheet 核對格線與字形。每次重跑都會產生新的 API 費用。原本 LINE webhook 預設仍使用暫存檔；上述完整紀錄由模擬腳本開啟。

`pipeline/cropped*` 等檔案是共用服務原有的預處理輸出；正式 LINE 逐格模型實際使用的是 `pipeline/grid/cells/`。定位失敗時會保留 `pipeline/registration-preview.png` 供檢查。
